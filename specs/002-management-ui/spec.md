# Feature Specification: 管理界面重构(002-management-ui)

**Feature Branch**: `002-management-ui`

**Created**: 2026-09-22

**Status**: Draft

**Input**: User description: "页面不能规划一下吗,和原来的完全没法比啊" —— 当前 001 实现的管理页面是可用的裸表格骨架,与参考项目(Ydisks-Xianyu-Helper 的 React 管理后台:数据看板、账号卡片、自动化中心、订单管理等成体系页面)相比,缺乏页面规划与视觉/交互品质。本规格为管理界面建立正式的页面级规划。

## Clarifications

### Session 2026-09-22

- Q: 规则编辑抽屉里的"匹配预览"应由谁计算匹配结果? → A: 后端预演——由服务端交付引擎同一套匹配逻辑计算的只读预演接口提供,界面只展示结果,保证预览结果与实际发货一致;不在浏览器端复现第二套匹配算法。
- Q: 概览页的统计数字与待处理计数采用什么刷新策略? → A: 概览页可见时每 30 秒自动轮询,并提供手动刷新按钮;订单、待处理等其他页面在进入或完成操作后刷新,不做全局轮询。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 统一布局与视觉框架 (Priority: P1)

卖家首次打开本地管理界面,看到的是一个成体系的管理后台:左侧固定侧边栏(产品标识、六个导航项、当前项高亮),顶部条(当前页面标题、管理员标识、退出登录),右侧内容区以卡片为单位组织信息。界面有统一的配色、间距、字号层级与状态语义色(正常=绿、警告=黄/橙、异常=红、中性=灰、进行中=蓝),默认浅色主题并提供暗色主题切换(记忆选择)。所有页面共享同一套通用组件词汇:卡片、表格、状态徽章、按钮(主/次/危险,不可用时禁用并提示原因)、表单控件、侧滑抽屉、居中弹窗、时间线、空状态插画与引导文案、加载骨架屏、错误重试块。窗口收窄时侧边栏自动折叠为图标条。

**Why this priority**: 布局框架与组件词汇是其余全部页面故事的地基;没有它,任何单页美化都无法形成"成体系"的观感,也无法消除用户"和原来完全没法比"的核心抱怨。

**Independent Test**: 打开任意一个页面即可验证:侧边栏/顶栏/卡片布局/主题切换生效;单独交付即已比裸表格有可感知的品质提升。

**Acceptance Scenarios**:

1. **Given** 已登录的管理员, **When** 在六个导航项之间切换, **Then** 每页呈现相同的侧边栏、顶栏与卡片化内容区,当前导航项高亮,内容区无裸无边框文本堆积。
2. **Given** 任意页面, **When** 点击主题切换, **Then** 全部页面(含重新打开的页面)保持同一主题,选择在下次打开时被记住。
3. **Given** 某接口请求失败, **When** 对应内容区渲染, **Then** 显示错误块(错误摘要 + 重试按钮)而非空白或裸错误文本;重试成功后恢复正常内容。
4. **Given** 某列表无数据, **When** 页面渲染, **Then** 显示空状态(说明文案 + 指向下一步动作的引导,如"还没有账号,去扫码接入")。
5. **Given** 某数据仍在加载, **When** 页面渲染, **Then** 显示骨架屏占位,不闪烁、不跳变布局。
6. **Given** 窗口宽度收窄, **When** 布局重排, **Then** 侧边栏折叠为图标条且内容不溢出、不出现横向滚动条(表格按 3.3 的降级规则处理)。

### User Story 2 - 概览工作台(仪表盘) (Priority: P1)

卖家登录后落在概览页,一屏看清经营与风险状况:顶部统计卡行(在线账号数/总账号数、今日订单数、今日已自动交付数、待人工处理数——待处理数非零时以警告色强调并可点击跳转;概览可见时每 30 秒自动刷新并提供手动刷新按钮);恢复隔离横幅(存在恢复核对未完成时,置顶显示醒目提示与"去核对"入口);账号状态速览(每账号一行:昵称、启停状态徽章、监控范围、最近心跳时间,异常账号排前);最近订单列表(最近 10 条:时间、账号、商品、金额、双轴状态标签);最近待处理摘要(最近 5 条:类别、订单号、等待时长);快捷动作区(扫码接入账号、同步商品、打开订单中心)。所有统计卡点击可下钻到对应页面(待处理→待处理页,订单→订单中心,账号→账号页)。

**Why this priority**: 概览是使用频率最高的入口页,直接决定"第一眼观感";同时它把 001 已实现的后端能力(账号、订单、待处理、恢复核对)汇总成经营视角,价值密度最高。

**Independent Test**: 用已有种子数据打开概览页即可验证统计卡、横幅、速览、最近列表与快捷入口;任何一块数据缺失时其余块独立降级显示。

**Acceptance Scenarios**:

1. **Given** 存在 2 个在线账号、3 条今日订单、1 条待处理、1 条未完成的恢复核对, **When** 打开概览页, **Then** 四张统计卡显示对应数字,待处理卡以警告色强调,顶部出现恢复隔离横幅。
2. **Given** 统计卡"待人工处理"显示 1, **When** 点击该卡, **Then** 跳转到待处理工作台。
3. **Given** 账号 A 心跳超时, **When** 渲染账号状态速览, **Then** A 排在列表首位并带异常徽章,正常账号按最近心跳时间排序。
4. **Given** 系统内无任何订单, **When** 打开概览页, **Then** 订单统计卡显示 0,最近订单区显示空状态引导,其余区块正常渲染。
5. **Given** 概览某子块接口失败, **When** 页面渲染, **Then** 仅该子块显示错误重试块,其余子块不受影响。
6. **Given** 概览页保持打开且可见, **When** 无任何操作经过 30 秒, **Then** 统计数字与待处理计数自动更新,更新过程不产生布局跳变;手动刷新按钮点击后立即更新。

### User Story 3 - 账号管理页 (Priority: P1)

账号页以卡片网格展示每个闲鱼账号:头像占位、昵称、平台号脱敏展示、状态徽章(在线/离线/令牌过期/已暂停/暂停中/封禁)、启停开关、最近心跳时间、监控范围标签。页面主操作是"扫码接入":点击后弹出居中弹窗,弹窗内呈现接入流程(等待二维码→展示二维码与剩余有效期倒计时→轮询状态→成功/失败/过期),过期后提供"重新获取"而不必关闭弹窗。账号卡上的启停开关切换时弹出确认弹窗(含影响说明:停用后该账号停止接单与发货),执行中显示"暂停中"过渡态,完成后徽章即时更新。每张卡提供"查看验证"入口(进入官方验证浏览器流程入口或其不可用时的说明,不伪称可用)。

**Why this priority**: 账号是一切自动化能力的前置条件;扫码接入是首次使用的必经流程,其体验直接决定工具能否被启用。

**Independent Test**: 在 mock/dev 数据上即可完整验证:无账号时的空状态引导 → 点扫码 → 弹窗流程(含过期重取)→ 账号卡出现 → 启停切换确认与过渡态 → 徽章更新。

**Acceptance Scenarios**:

1. **Given** 无任何账号, **When** 打开账号页, **Then** 显示空状态(说明 + 醒目的"扫码接入"引导按钮)。
2. **Given** 点击"扫码接入", **When** 弹窗打开, **Then** 按流程阶段依次展示等待/二维码+倒计时/轮询中/结果,各阶段文案明确,不出现无反馈的死等。
3. **Given** 二维码已过期, **When** 弹窗仍打开, **Then** 展示过期提示与"重新获取"按钮;点击后回到二维码阶段,无需关闭弹窗重来。
4. **Given** 账号处于在线状态, **When** 点击启停开关, **Then** 先弹出确认弹窗说明影响;确认后卡片进入"暂停中"过渡态,完成后状态徽章更新为已暂停;取消则无任何变更。
5. **Given** 某账号令牌已过期, **When** 渲染账号卡, **Then** 状态徽章为"令牌过期"(警告色)并排在正常账号之前,卡片提供续期/重新扫码引导。

### User Story 4 - 商品与发货规则页 (Priority: P1)

商品区以表格展示商品:缩略图占位、标题(超长截断悬浮全文)、价格、状态(在售/下架)、是否已配置规则徽章、所属账号;顶部为筛选行(按账号、按是否已配置规则、关键字)与"从平台同步"按钮(同步中显示进行态,完成后以行内反馈展示新增/更新/失败计数,失败时可展开明细)。规则区以商品为主视角展示发货规则(每个已配置规则的商品一行:商品、卡密组/内容来源、发货延迟、消息模板摘要、启停状态),点击行打开右侧编辑抽屉。编辑抽屉包含完整表单:内容来源选择、模板内容多行输入(带字数统计与占位符插入按钮)、发货延迟设置、启用开关;表单实时校验(必填、字数上限、占位符合法性)并以行内错误提示;对同一商品存在重复/冲突配置时在保存前给出明确警告;抽屉底部提供"匹配预览":输入一条示例商品标题,即时显示将命中的规则与最终将发送的成品内容(脱敏),帮助卖家在保存前确认规则正确。

**Why this priority**: 发货规则是本工具的核心业务对象;规则配置错误直接导致发错内容,匹配预览与实时校验是防错的关键交互。

**Independent Test**: 用种子商品即可验证:筛选与同步反馈、打开抽屉编辑并实时校验、保存后列表即时更新、匹配预览命中正确规则。

**Acceptance Scenarios**:

1. **Given** 已有 20 个商品其中 3 个配置了规则, **When** 切换筛选"仅看已配置规则", **Then** 表格只显示 3 行且每行带"已配置"徽章。
2. **Given** 点击"从平台同步", **When** 同步执行中, **Then** 按钮进入进行态且不可重复点击;完成后显示"新增 N / 更新 M / 失败 K"反馈,K>0 时可展开失败明细。
3. **Given** 打开某商品的规则编辑抽屉, **When** 模板内容为空或超出字数上限, **Then** 保存按钮禁用/拒绝保存,对应字段下方显示行内错误说明。
4. **Given** 抽屉中输入示例商品标题, **When** 点击"匹配预览", **Then** 即时显示命中的规则名与最终发送内容预览;无命中时显示"无规则命中,将不自动发货"的明确说明。
5. **Given** 正在编辑抽屉, **When** 直接关闭抽屉, **Then** 提示有未保存修改,确认放弃后才丢弃。

### User Story 5 - 订单中心与订单详情 (Priority: P1)

订单页顶部为筛选栏:订单号搜索、账号下拉、内容状态(已交付/重试中/失败/人工处理中…)、平台状态、时间范围;支持组合筛选与清空。表格列:下单时间、订单号(超长截断)、账号、商品标题、金额、双轴状态标签(内容状态为主标签,审核/确认状态为副标签,各用语义色)、发货方式(自动/人工接管);底部分页(每页条数固定,上一页/下一页 + 页码信息,翻页保留筛选条件)。点击任意行打开右侧详情抽屉:订单基本信息、三轴状态时间线(各状态变更节点按时间排列)、交付尝试记录(每次尝试的时间/结果/重试倒计时)、交付内容揭示(默认折叠,点击展示,防止肩窥时的内容裸露)、人工动作区(该订单当前 guard 允许的操作按钮;不可用操作不隐藏而是禁用并说明原因)。人工接管的订单打上"人工接管"标识。

**Why this priority**: 订单是交付闭环的审计核心;出现纠纷时卖家需要在订单详情里完整还原"发生了什么、发了什么、为什么",这是 001 交付不变量的用户侧呈现。

**Independent Test**: 用种子订单即可验证:组合筛选、分页保持筛选、详情抽屉三轴时间线与尝试记录完整、内容揭示交互、人工动作按 guard 启停。

**Acceptance Scenarios**:

1. **Given** 100 条订单分布在 2 个账号, **When** 选择账号 A 并输入部分订单号, **Then** 表格仅显示账号 A 中匹配该订单号的记录,筛选栏显示当前条件并提供"清空筛选"。
2. **Given** 某订单经历 1 次失败与 1 次重试成功, **When** 打开其详情抽屉, **Then** 时间线呈现状态变更节点,尝试记录列出 2 次尝试及各自结果。
3. **Given** 详情抽屉中的交付内容默认折叠, **When** 点击揭示, **Then** 展示完整交付内容;再次点击可重新折叠。
4. **Given** 订单处于 unknown 人工核对中, **When** 查看人工动作区, **Then** 仅显示 guard 允许的操作;被 guard 阻止的操作以禁用态展示并附阻止原因,绝不出现点击后才报错的暗坑。
5. **Given** 在第 2 页且带筛选条件, **When** 点击上一页, **Then** 返回第 1 页且筛选条件保留;总页数为 1 时翻页控件禁用。

### User Story 6 - 待处理工作台 (Priority: P2)

待处理页按类别分组呈现全部待人工事项(恢复核对、unknown 交付核对、接管订单、令牌过期等),每组显示计数徽章与组内条目:类别图标、标题、关联订单号/账号、等待时长(越久越警示)、风险提示文案、该条目当前允许的操作按钮。执行操作走统一确认流:弹窗中说明操作影响、必填原因(恢复核对类)、高危操作需勾选风险确认;提交后按钮进入进行态,成功后该条目以动画移出列表且组计数即时减一。页面顶部显示总待处理数与最久等待时长。

**Why this priority**: 待处理是安全网(unknown 永不自动重发)的用户侧出口;体验要求低于核心页面但仍需成体系,故 P2。

**Independent Test**: 用种子待处理事项即可验证:分组与计数、确认流(含必填原因与风险勾选的强制性)、完成后条目移出与计数联动。

**Acceptance Scenarios**:

1. **Given** 存在 2 条恢复核对与 1 条 unknown 核对, **When** 打开待处理页, **Then** 两组分别呈现条目与计数,顶部总数为 3,最久等待时长正确。
2. **Given** 对一条恢复核对点击"确认放行", **When** 确认弹窗打开, **Then** 原因输入为空时无法提交;填写原因并勾选风险确认后可提交。
3. **Given** 某操作已提交, **When** 等待后端响应, **Then** 按钮为进行态不可重复点击;成功后该条目移出列表,组计数与总数即时更新。
4. **Given** 无任何待处理事项, **When** 打开待处理页, **Then** 显示"全部处理完毕"的正向空状态(而非空白)。

### User Story 7 - 设置与安全页 (Priority: P2)

设置页以分组卡片组织:**运行信息**(版本号、数据目录路径、监听地址、当前执行模式、运行时长);**备份与恢复**(说明 + 发起备份/恢复的操作指引,恢复完成后引导跳转待处理页完成核对);**安全**(管理员会话剩余有效期、上次登录时间、修改管理员密码的引导说明与 CLI 重置指引);**关于**(本地运行、数据不出本机的说明)。所有危险操作(恢复)均走确认流并明确后果(恢复后进入隔离态、全部会话吊销)。

**Why this priority**: 设置页是低频但承担信任建设(数据本地化、备份能力可见)的页面;不阻塞核心链路,故 P2。

**Independent Test**: 打开设置页即可验证运行信息正确渲染、恢复操作有完整确认与后果说明。

**Acceptance Scenarios**:

1. **Given** 服务已运行, **When** 打开设置页, **Then** 运行信息卡显示与实际一致的版本/数据目录/监听地址/执行模式。
2. **Given** 点击"恢复备份"入口, **When** 确认弹窗打开, **Then** 明确列出后果(进入恢复隔离、会话吊销、需完成核对);未确认前不执行任何动作。
3. **Given** 曾完成一次备份, **When** 查看备份卡, **Then** 显示最近备份时间;从未备份则显示引导文案。

### User Story 8 - 登录与初始化体验 (Priority: P2)

首次启动(未初始化)时,初始化页以居中卡片呈现:产品标识、管理员密码设置表单(强度提示、≥12 字符校验、二次确认输入、行内错误)、数据目录展示与安全说明。已初始化后,登录页同样是品牌化居中卡片(密码输入、错误行内提示、登录中按钮态)。会话过期时,任意操作自动回落到登录页,重新登录后回到之前所在页面(而非固定回概览)。

**Why this priority**: 登录/初始化是门面但功能上已可用(001 已实现 auth gate),本故事是品质化打磨,故 P2。

**Independent Test**: 清空数据目录启动可验证初始化表单校验;退出后重新登录可验证登录卡片与会话回落行为。

**Acceptance Scenarios**:

1. **Given** 未初始化的数据目录, **When** 打开界面, **Then** 呈现初始化卡片;两次密码不一致或长度不足时,提交被阻止并显示行内错误。
2. **Given** 会话已过期, **When** 用户在订单页点击任一操作, **Then** 界面平滑回落到登录页;重新登录成功后回到订单页。
3. **Given** 登录密码错误, **When** 提交, **Then** 按钮恢复可用并显示行内错误提示(不暴露具体是密码错误的敏感细节以外信息)。

---

### Edge Cases

- 会话在操作进行中过期:操作失败后不得静默丢失用户上下文,须回落登录并在重登后恢复原页面(US8-2)。
- 状态枚举未知的订单/账号(平台新增枚举):界面必须渲染为"未知状态"中性徽章并保留原始值悬浮展示,不得崩溃或显示空白。
- 长文本(商品标题、订单号、昵称):统一截断 + 悬浮/点击查看全文,不得撑破布局。
- 时间显示:统一使用本地时区与相对时间(如"3 分钟前"),悬浮显示绝对时间;等待时长随时间自然增长无需手动刷新即可更新。
- 分页边界:筛选后结果数小于页大小时翻页禁用;筛选无结果时显示带引导的空状态而非空表格。
- 弹窗/抽屉叠层:同时只允许一层遮罩交互;抽屉内触发确认弹窗时层级正确,关闭后焦点回到触发元素。
- 二维码轮询长时间无响应:显示"仍在等待"的进行态与取消按钮,不得无限白屏。
- 操作目标已被他人/他进程变更(如账号已被停用):界面以最新服务端状态刷新并提示,不得基于过期状态继续操作。
- 暗色主题下语义色仍可区分(对比度可读),图表/徽章不因主题切换失去语义。
- 键盘可用性:弹窗 Esc 关闭(有未保存修改时先确认)、抽屉内表单可 Tab 遍历、按钮可 Enter 触发。

## Requirements *(mandatory)*

### Functional Requirements

**布局与框架**

- **FR-001**: 系统 MUST 提供统一的页面框架:固定侧边栏导航(概览/账号/商品与发货规则/订单/待处理/设置)、顶栏(页面标题、管理员标识、退出)与卡片化内容区,并覆盖全部六类页面。
- **FR-002**: 系统 MUST 提供浅色/暗色主题切换,记忆用户选择,且全部页面与通用组件在两种主题下保持语义色一致可辨。
- **FR-003**: 系统 MUST 为所有异步数据区域提供三种标准状态:加载骨架屏、空状态(含引导动作)、错误块(含重试);不得出现无反馈的空白区域。
- **FR-004**: 系统必须定义并全局复用一套状态语义色规范(正常/警告/异常/中性/进行中),所有徽章、统计卡、时间线节点遵循该规范。
- **FR-005**: 所有破坏性或不可逆操作(停用账号、恢复备份、放行恢复核对等)MUST 经过确认弹窗,说明影响;执行期间按钮呈进行态且不可重复触发。

**概览**

- **FR-006**: 概览页 MUST 展示统计卡:账号(在线/总数)、今日订单数、今日已自动交付数、待人工处理数(统计口径为本地时区自然日);每张统计卡可下钻到对应页面,待处理数非零时以警告色强调。概览页可见时统计与待处理计数 MUST 每 30 秒自动刷新,并提供手动刷新按钮;刷新不得造成布局跳变。
- **FR-007**: 概览页 MUST 在存在未完成恢复核对时置顶显示恢复隔离横幅,提供直达核对入口。
- **FR-008**: 概览页 MUST 展示账号状态速览(异常优先排序)、最近订单(含双轴状态)与最近待处理摘要,各子块独立降级。

**账号**

- **FR-009**: 账号页 MUST 以卡片视图展示账号,含状态徽章(在线/离线/令牌过期/已暂停/暂停中/封禁)、启停控制、最近心跳时间与监控范围;异常状态账号排序靠前。
- **FR-010**: 扫码接入 MUST 以弹窗内完整流程呈现(等待二维码→二维码+有效期倒计时→轮询→结果),二维码过期时支持弹窗内重新获取。
- **FR-011**: 当前执行配置下不可用的能力入口(如 live 构建中的官方验证、平台同步等尚未接入真实协议的功能)MUST 明确展示不可用状态与原因,不得伪称可用(宪章:不虚报能力)。

**商品与规则**

- **FR-012**: 商品列表 MUST 支持按账号/是否已配置规则/关键字筛选,并提供平台同步按钮与同步结果反馈(新增/更新/失败计数,失败明细可展开)。
- **FR-013**: 规则编辑 MUST 在侧滑抽屉中完成,表单具备实时行内校验(必填、字数上限、占位符合法性),存在未保存修改时关闭须确认。
- **FR-014**: 规则编辑抽屉 MUST 提供匹配预览:输入示例商品标题,即时展示由服务端交付引擎同一套匹配逻辑计算的只读预演结果(命中规则与最终发送内容预览);无命中时明确提示不自动发货。界面不得在浏览器端复现第二套匹配算法,防止预览与实际发货漂移。

**订单**

- **FR-015**: 订单列表 MUST 支持组合筛选(订单号、账号、内容状态(001 定义的全部枚举值)、平台状态、时间范围)与分页,翻页保留筛选条件。
- **FR-016**: 订单列表与详情 MUST 以双轴状态标签呈现(内容状态主标签、审核/确认状态副标签),人工接管订单有专属标识。
- **FR-017**: 订单详情抽屉 MUST 呈现三轴状态时间线、全部交付尝试记录、默认折叠可揭示的交付内容,以及按 guard 实时启停的人工动作区(不可用操作禁用并注明原因)。

**待处理与设置**

- **FR-018**: 待处理工作台 MUST 按类别分组展示条目(计数、等待时长、风险提示、允许操作),操作走统一确认流;放行、重发等改变交付结果的人工操作一律原因必填,高危操作须勾选风险确认;完成后条目即时移出且计数联动。
- **FR-019**: 设置页 MUST 展示运行信息(版本、数据目录、监听地址、执行模式)、备份/恢复操作指引(含恢复后果说明)、会话与安全信息。
- **FR-020**: 初始化/登录 MUST 以品牌化卡片呈现,表单行内校验;会话过期自动回落登录,重登后恢复原页面。
- **FR-021**: 系统 MUST 妥善渲染未知枚举值:显示"未知状态"徽章并保留原始值可见,不得崩溃或空白。
- **FR-022**: 系统 MUST 保证本次重构不改变 001 已定义的 API 行为与交付安全不变量;界面原则上仅消费既有 API,确需新增的只读接口(匹配预演、概览统计聚合)须在计划阶段按 001 边界复核,不得改变既有契约语义与安全约束。

### Key Entities *(include if feature involves data)*

- **页面框架(Layout)**: 侧边栏 + 顶栏 + 内容区的三区结构;导航项与路由的映射;主题状态。全部页面共享,是组件词汇的容器。
- **通用组件词汇表(Component Vocabulary)**: 卡片、表格、状态徽章、按钮层级、表单控件、侧滑抽屉、居中弹窗、时间线、空状态、骨架屏、错误重试块。规格只约束行为与语义,不约束具体实现库。
- **状态语义色(Semantic Status Colors)**: 正常/警告/异常/中性/进行中五类语义到视觉呈现的映射,全局唯一,主题切换下保持可辨。
- **统计卡(Stat Card)**: 概览页的数字+标签+下钻目标单元,含强调规则(待处理非零告警)。
- **双轴状态标签(Status Tags)**: 订单的内容状态(主)与审核/确认状态(副)的成对呈现方式。
- **确认流(Confirmation Flow)**: 破坏性操作的统一交互模式:影响说明→(必填原因/风险勾选)→进行态→结果反馈。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-201**: 六类页面(概览/账号/商品与规则/订单/待处理/设置)+ 登录/初始化全部套用统一布局框架与组件词汇,视觉走查清单(布局一致性、语义色一致、间距字号层级)100% 通过。
- **SC-202**: 每个含异步数据的页面区域均具备加载/空/错误三态,抽查清单 100% 覆盖,无裸空白区域。
- **SC-203**: 核心任务点击深度达标:概览→某订单详情 ≤3 次交互;处理一条待处理事项(含确认流)≤5 次交互;扫码接入从打开账号页到看到二维码 ≤2 次交互。
- **SC-204**: 概览统计卡数字与对应列表页实际条目数一致(种子数据核对),待处理计数与待处理页条目数一致。
- **SC-205**: 全部平台状态/账号状态枚举(含构造的未知枚举值)在界面正确渲染,无崩溃、无空白、无误导性显示;语义色映射覆盖率 100%。
- **SC-206**: 001 的既有测试全部保持通过(97 项),API 契约无破坏性变更;交付安全不变量(unknown 不自动重发、guard 互斥、重试预算)在界面上的呈现与其语义一致。
- **SC-207**: 前端构建产物(压缩后,含全部页面与样式)总体积 ≤1.5 MB;概览页首屏可交互时间 ≤2 秒(本地环境);构建产物仍嵌入二进制,版本一致性校验保持有效。

## Assumptions

- 范围沿用 001 的界面边界:本规格只覆盖 001 已定义的六类页面与登录/初始化;完整客服会话中心、AI 回复、卡密库存管理、批量铺货、评价/擦亮、外部通知渠道等上游项目功能仍属 001 排除项,不在本规格内。
- 参考项目(Ydisks-Xianyu-Helper)仅作为信息架构与页面品质的参照,不构成逐像素复刻承诺(沿用 001 边界条款)。
- 技术栈沿用现有 TypeScript + Vite 原生 DOM 方案,不强制引入前端框架;若 plan 阶段评估后选择引入,须保持构建产物仍嵌入二进制且 release 版本一致性校验不变。
- 概览"今日订单/已交付"统计口径默认采用本地时区自然日;若后端无对应聚合端点,plan 阶段评估最小聚合接口(不改变 001 契约语义)。
- 数据均来自 001 已实现的 API;界面重构不新增业务数据存储。确需新增的只读接口(匹配预演、概览聚合)见 FR-022 约束。
- 单管理员本地使用场景不变,不做多用户/权限分级设计。
- 浏览器支持范围:桌面端最新版 Edge/Chrome/Firefox;不做移动端完整适配与旧版浏览器支持(窄窗口降级见 FR/边界条款)。
- 界面语言仅中文,不做多语言设计。
- 规则内容为纯固定文本:001 引擎按原样发送、无占位符替换体系(收敛核查 T068 口径对齐);US4 叙述中的"占位符插入按钮"据此不实现,抽屉帮助文案如实说明能力边界(宪章:不虚报能力)。
