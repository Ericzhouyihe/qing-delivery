# Contract: 匹配预演端点(既有,本文档为消费方记录)

**Date**: 2026-09-22 | **Change type**: 无变更(消费既有 T059 端点)| **Spec**: FR-014/澄清决定/US4

匹配预览的权威计算方为服务端交付引擎(同一套精确匹配逻辑)。本特性**不修改**以下端点,仅记录 UI 消费契约。

## 1. POST /api/accounts/{account_id}/rules/match-preview

```text
Cookie: qing_session=...      X-CSRF-Token: ...(POST,既有要求)
{ "item_id": "…", "sku_key": "…" }
```

**200**:

| result | 语义 | UI 呈现 |
|---|---|---|
| `matched` | 恰好一条启用规则命中(附 rule_id/rule_version) | 绿色徽章+规则信息,随后调渲染预览展示最终内容 |
| `none` | 无启用规则命中 | 明确提示"无规则命中,将不自动发货" |
| `ambiguous` | 多条启用规则命中 | 冲突警告(对应 US4 重复/冲突配置警告),引导去重 |

**前端约束**:不得在浏览器端实现任何匹配判定;商品/规格选择只是定位 `item_id/sku_key` 的输入手段(本地过滤已同步目录,非匹配逻辑)。

## 2. POST /api/accounts/{account_id}/rules/preview

输入 `{ "content": "模板文本" }`,输出占位符渲染后的最终内容预览。UI 用它展示"最终将发送的成品内容";不在前端实现占位符替换。

## 3. 边界行为

- 未初始化/未登录 → 401/403,前端回落登录(US8)。
- 账号不存在/无权限 → 既有错误码原样呈现于错误块。
- 预演请求不产生任何交付副作用(端点语义为只读判定,维持 T059 行为)。
