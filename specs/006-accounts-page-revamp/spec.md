# Feature Specification: 账号管理页面复刻与视图切换(006-accounts-page-revamp)

**Feature Branch**: `006-accounts-page-revamp`

**Created**: 2026-09-25

**Status**: Draft

**Input**: User description: "账号页面前期复刻的不到位，先完美复刻下来这个页面，然后加一个卡片视图切换的按钮。"参考截图为 Ydisks 闲鱼助手的"账号管理"页:页头大标题+副标题、搜索框(搜索昵称/备注/账号ID)与"扫码添加新账号"主按钮、浅蓝计数横幅(当前显示 X / Y 个账号+刷新资料/重新授权提示)、账号条目(圆形头像+右下角状态圆点、昵称+能力徽标行、备注+ID 行、安全验证红色警示条+行内"重新授权"、右侧纯图标操作组)。用户在自己页面上的批注:搜索框放在工具栏左侧;新增视图切换按钮只显示图标不显示文字,放在扫码按钮旁边,样式做的好看一点。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 页面框架与搜索过滤 (Priority: P1)

卖家打开账号管理页,看到与参考页面一致的页头:大标题"账号管理",下方副标题"管理您的闲鱼授权账号及设置。建议给账号填写备注，便于多账号区分。";同一页头区域内,搜索框(占位文案"搜索昵称 / 备注 / 账号ID")靠左,右侧依次为视图切换控件与主按钮"扫码添加新账号"(带二维码图标)。搜索框下方是浅色信息横幅:左侧"当前显示 X / Y 个账号",右侧固定提示"如果某个账号只显示 ID，点该账号右侧"刷新资料"；若刷新失败，先点二维码重新授权。"卖家在搜索框输入关键词时,列表按昵称、备注、账号 ID 实时过滤,横幅计数同步更新。

**Why this priority**: 页头框架是"完美复刻"的第一观感,搜索是账号变多后定位账号的主要手段;没有框架,条目与切换无处安放。

**Independent Test**: 打开账号页对照参考截图核对页头四要素(标题区、搜索框、主按钮、计数横幅),再输入已知备注关键词验证过滤与计数。

**Acceptance Scenarios**:

1. **Given** 系统内至少有 1 个账号, **When** 打开账号页, **Then** 页头标题、副标题、搜索框、主按钮、计数横幅齐全,文案与参考页面一致。
2. **Given** 两个账号中仅一个的备注含"测试", **When** 在搜索框输入"测试", **Then** 列表只显示匹配账号,横幅更新为"当前显示 1 / 2 个账号"。
3. **Given** 输入内容为昵称片段、备注片段或账号 ID 片段(含大小写混排、首尾空格), **When** 输入变化, **Then** 结果即时更新,无需回车或点击按钮;匹配不区分大小写。
4. **Given** 搜索框有内容, **When** 清空搜索框, **Then** 列表恢复显示全部账号,横幅恢复完整计数。
5. **Given** 卖家点击"扫码添加新账号", **When** 扫码授权成功, **Then** 打开现有扫码接入流程,新账号出现在列表中。

---

### User Story 2 - 账号条目复刻 (Priority: P1)

列表中每个账号条目按参考样式呈现:左侧圆形头像,右下角叠加在线状态小圆点(在线为绿色,非在线为灰/红色);第一行为账号昵称(粗体)与状态、能力徽标(如黄色"需要验证"、"自动发货"、"自动确认"等);第二行为备注(无备注时显示灰色"暂无备注")与"ID: 完整账号 ID"。需要安全验证或授权失效的账号,在条目中部显示红色警示文案"闲鱼要求安全验证，请重新扫码并完成验证"与浅红底色"重新授权"行内按钮;条目右侧是一排纯图标操作按钮(刷新资料、重新授权二维码入口、编辑、启用/停用、删除),悬停出现文字提示与颜色反馈,删除为危险红色。异常账号排序置顶。

**Why this priority**: 条目是账号页的主体,视觉与操作是否"完美复刻"直接由它体现;但它渲染在框架之内,故与 US1 同级并列实现。

**Independent Test**: 造一个在线账号与一个需验证账号,逐项核对头像圆点、徽标、备注/ID 行、警示条与图标操作组的展示,并逐个点击操作验证行为。

**Acceptance Scenarios**:

1. **Given** 一个处于"需安全验证"的账号, **When** 渲染条目, **Then** 显示"需要验证"徽标、红色警示文案与"重新授权"行内按钮;点击"重新授权"打开扫码流程,授权成功后警示消失。
2. **Given** 在线账号与离线账号各一, **When** 渲染条目, **Then** 头像右下角圆点呈现可区分的在线/非在线状态。
3. **Given** 一个无备注账号, **When** 渲染条目, **Then** 第二行显示"暂无备注"与完整账号 ID。
4. **Given** 卖家依次点击刷新资料、编辑、电源、删除图标, **When** 各操作执行, **Then** 分别触发资料刷新、备注/开关编辑、启停确认弹窗、删除确认弹窗;行为与复刻前一致。
5. **Given** 任意图标按钮, **When** 鼠标悬停, **Then** 显示对应功能文字提示;删除按钮悬停呈红色危险反馈。

---

### User Story 3 - 图标式视图切换 (Priority: P2)

工具栏主按钮左侧提供仅以图标呈现(无文字)的视图切换控件:列表视图与卡片视图各对应一个图标,当前视图的图标有明确激活高亮,悬停显示文字提示。点击图标即在两种视图间切换,切换后偏好被记忆,再次进入账号页保持;两种视图应用相同的搜索过滤与异常置顶排序。

**Why this priority**: 用户明确要求的新交互,但依赖条目(US2)先存在才有视图可切,故列 P2。

**Independent Test**: 在工具栏找到纯图标切换控件,点击切换列表/卡片并刷新页面验证记忆;在搜索过滤激活时切换,验证两视图结果一致。

**Acceptance Scenarios**:

1. **Given** 当前为列表视图, **When** 查看工具栏, **Then** 视图切换控件只显示图标、不显示文字,列表图标呈激活态,悬停有文字提示。
2. **Given** 点击卡片图标, **When** 切换完成, **Then** 列表以卡片形式呈现且卡片图标激活;刷新页面后仍为卡片视图。
3. **Given** 搜索过滤已生效(仅 1 个可见账号), **When** 切换视图, **Then** 两种视图都只显示该过滤后账号。

---

### Edge Cases

- 搜索无匹配:横幅显示"当前显示 0 / N 个账号",列表区显示"无匹配账号"类空态提示,与"还没有接入账号"的整页空态明确区分。
- 账号总数为 0(新装系统):保留现有引导接入空态,计数横幅不显示误导性内容。
- 头像图片加载失败:回退为昵称首字占位,不显示破图图标。
- 超长昵称、备注或 ID:截断省略,不破坏条目布局;完整 ID 可通过悬停提示或既有复制能力获得。
- 列表加载中或接口失败:显示加载骨架/错误占位与重试入口,页头与工具栏保持稳定不闪烁。
- 账号状态在停留期间变化(验证通过、授权失效):下次刷新后徽标、警示条与排序如实更新。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 账号页 MUST 在内容区呈现页头:标题"账号管理"与副标题"管理您的闲鱼授权账号及设置。建议给账号填写备注，便于多账号区分。"
- **FR-002**: 页头 MUST 提供搜索框(占位文案"搜索昵称 / 备注 / 账号ID")与主按钮"扫码添加新账号"(带二维码图标);视图切换控件位于主按钮左侧,搜索框位于工具栏左侧。
- **FR-003**: 搜索 MUST 对昵称、备注、账号 ID 做不区分大小写的子串匹配,输入变化即时生效,无需回车;清空后恢复全部账号。
- **FR-004**: 列表上方 MUST 常驻信息横幅:左侧显示"当前显示 X / Y 个账号"(X 为当前过滤后可见数,Y 为账号总数),右侧显示固定操作提示文案(与参考页面一致)。
- **FR-005**: 每个账号条目 MUST 按参考布局呈现:圆形头像与右下角在线状态圆点;首行为昵称(粗体)与状态/能力徽标;次行为备注(空时"暂无备注")与完整账号 ID。
- **FR-006**: 需要安全验证或授权失效的账号 MUST 在条目内显示红色警示文案与"重新授权"行内入口,点击打开扫码重新授权流程;此类账号 MUST 排序置顶。
- **FR-007**: 每个条目 MUST 提供纯图标操作组,至少包含:刷新资料、编辑、启用/停用、删除,并为需重新授权的账号提供强调样式的重新授权入口;每个图标按钮 MUST 有悬停文字提示与悬停视觉反馈,删除使用危险红色。
- **FR-008**: 界面上的徽标与操作 MUST 仅映射系统真实具备的能力与状态(如需要验证、自动发货、自动确认、在线/离线),MUST NOT 为对齐参考图展示尚不存在的功能(如 AI、自动评价、每日擦亮)。
- **FR-009**: 工具栏 MUST 提供仅以图标呈现(不含文字)的列表/卡片视图切换控件,当前视图有明确激活高亮,悬停有文字提示。
- **FR-010**: 视图偏好 MUST 在切换后持久记忆,再次进入账号页保持;列表与卡片视图 MUST 应用相同的搜索过滤与异常置顶排序。
- **FR-011**: 加载、错误与空态 MUST 有明确占位:加载骨架、错误提示与重试、无账号引导、搜索无匹配提示;数据加载期间页头与工具栏保持稳定。
- **FR-012**: 既有能力 MUST NOT 回退:扫码接入、刷新资料、编辑备注与自动化开关、启停确认流、删除确认、验证入口在复刻后全部保留且行为不变。

### Key Entities *(include if feature involves data)*

- **账号**(既有):昵称、备注、账号 ID、头像、连接状态(在线/连接中/需验证/授权失效/停用)、自动化开关(自动发货、自动平台确认)。本特性不新增业务数据实体,仅改变呈现与过滤。
- **视图偏好**:账号页"列表/卡片"视图的用户选择,跨会话记忆。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对照参考截图逐项核对(页头标题区、搜索框、主按钮、计数横幅、条目头像+圆点、徽标行、备注/ID 行、警示条、图标操作组),视觉元素齐全率 100%,文案与参考一致(能力徽标按 FR-008 如实裁剪)。
- **SC-002**: 输入搜索关键词后,可见列表与横幅计数在下一次渲染内更新(无可感知延迟,不超过 1 秒)。
- **SC-003**: 视图切换单次点击完成且不整页刷新;刷新页面后视图偏好保持率 100%。
- **SC-004**: 卖家在这一个页面内即可完成搜索定位、刷新资料、编辑备注、启停、重新授权、删除全部账号操作,无需跳转其他页面。
- **SC-005**: 界面上出现的每个徽标与按钮均对应真实可用能力(无虚标),审核通过率 100%。

## Assumptions

- 参考图中的"AI、自动评价、每日擦亮"徽标及机器人、日历图标对应本项目首版不具备的能力;按宪章"如实展示"原则不复刻为可用功能,仅复刻其视觉样式并映射到真实能力徽标(需要验证/自动发货/自动确认/在线状态);未来能力上线后可按相同样式扩展。
- 主按钮文案采用参考图的"扫码添加新账号"(取代现有"＋ 扫码接入"),点击行为复用现有扫码接入流程。
- "只显示图标、做的好看一点"具体化为:列表/卡片双图标分段控件,当前项高亮,置于主按钮左侧;不采用带文字的整宽按钮。
- 全局布局(侧边导航、顶栏、主题)不在本特性范围,仅改造账号页内容区;页内标题"账号管理"不改变侧边导航既有文案。
- 搜索过滤作用于当前已加载的账号列表;目标用户为个人卖家,账号规模为几十以内,不考虑分页与后端检索。
- 参考页面中的"退出登录、收起侧边栏、运行版本"等全局元素不属于本特性范围。
