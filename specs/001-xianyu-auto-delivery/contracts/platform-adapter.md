# Platform Adapter Contract: 闲鱼接入与外部动作

**Status**：设计契约，2026-09-22；尚未实现、未进行真实账号或订单验证。

依据：[需求](../spec.md)、[实现决策](../research.md)。本契约描述应用层消费的平台能力，
不是对闲鱼接口长期稳定性的承诺。上游 `Ydisks-Xianyu-Helper/` 仅供研究，不参与构建、
运行、发行包或测试环境初始化；确定性夹具必须独立建立并脱敏。

## 1. 所有权与接口边界

- 应用层定义最小消费者接口；闲鱼适配器实现协议和浏览器机制，不决定规则匹配、
  自动补发、人工授权、重试预算或业务事务，不直接写业务数据库。
- 每个账号执行器独占当前连接、凭证代次、请求关联集合和外部动作入口；不同账号隔离。
  运行任务有明确取消源、退出和 Join 路径，消息队列有界，过载显式报告。
- 平台返回具类型的事实、证据和错误；原始 Cookie、Token、正文不得进入普通日志、
  事件摘要或 HTTP 错误。诊断使用安全错误码和不含秘密的关联标识。
- 应用层负责持久化事件、订单事实、尝试和人工处理事项；数据库不可用时不开始新发送。
  平台层不得在数据库事务或业务互斥锁内执行网络、浏览器及人工等待。

| 消费者能力 | 输入与输出语义 | 外部副作用 |
| --- | --- | --- |
| `start_authorization` / `observe_authorization` / `cancel_authorization` | 创建短期授权会话，观察二维码、验证要求、授权结果和失效；绑定会话代次 | 平台登录请求；不能据此宣称账号在线 |
| `start_account` / `stop_account` | 使用指定凭证代次建立或结束 Token/WS 会话，输出运行状态和事件流 | 连接、注册、心跳；停止必须等待后台任务结束 |
| `refresh_credentials` | 区分签名 Token 更新与登录会话续期，返回作用域完整的凭证变更和原代次 | 认证请求；不能在此自动重放业务动作 |
| `list_products` | 分页商品、完整规格描述、上下架事实及完整性报告 | 只读查询 |
| `trace_sold_orders` | 目标时间范围、分页游标和预算；输出候选订单与覆盖报告 | 只读查询；不是发货指令 |
| `fetch_order_snapshot` | 账号、订单 ID、必要事实要求；返回可信结构化快照或缺失项 | 协议优先，必要时浏览器读取 |
| `resolve_conversation` | 已核对的账号、买家、商品或订单关联；返回经过验证的会话身份 | 读取或建立会话；若有副作用须走账号动作屏障 |
| `send_text` | 不可变内容快照、请求 ID、账号/买家/会话、控制及凭证代次 | 一次消息提交，返回证明或未知；不内建盲目重试 |
| `confirm_shipment` | 经应用授权的订单和原交付证明、独立请求 ID | 一次平台发货确认，结果独立于内容交付 |
| `verify_shipment_state` | 订单身份和待核对确认请求 | 只读复核，不能重新发送正文 |

以上是语义接口，不要求逐项拆出 Trait 或包；实现可以合并具有相同生命周期的能力，
不能增加万能接口、动态服务定位器，或让平台适配器接管业务状态机。

## 2. 通用身份、时间与错误

- 所有平台 ID 使用不透明字符串，不用 JavaScript Number 表达长整型 ID。
  身份至少含 `platform`、内部 `account_id`、平台卖家 ID；订单再含平台订单 ID。
- 请求携带 `operation_id`、取消上下文、截止时间、`credential_generation`；
  外部变更另含 `control_generation`、关联内容版本和应用签发的执行资格。
- 内部时间统一 UTC，可使用 RFC 3339；平台秒/毫秒必须按字段协议转换，不能靠数值猜测。
  快照分别记录事实时间、`observed_at` 和来源；接收时间不是付款时间。
- 错误分类至少包括：`cancelled_before_submit`、`timeout`、`rate_limited`、
  `network_unavailable`、`signing_token_expired`、`session_expired`、
  `verification_required`、`business_rejected`、`unsupported`、`malformed_response`、
  `incomplete_facts`、`browser_unavailable`。动作提交状态另行返回，不能仅凭错误名称决定重试。
- 未知字段可以忽略，改变身份、金额、状态、分页或规格含义的未知值必须暴露为不完整或未知，
  不能套默认正常值。未经来源证实的状态不得提升为已付款、已交付或已发货。

## 3. 结构化事件与批量推送

事件信封包含账号范围、连接/凭证代次、平台事件 ID（如存在）、本地接收 ID、
平台事件时间（如存在）、接收时间、证据来源和具类型载荷。规范事件包括：

- `authorization_changed`：等待扫码、已扫码、需要官方验证、授权完成、失效或取消。
- `account_runtime_changed`：连接中、在线、离线、需授权、需验证；授权完成与在线分开。
- `order_payment_signal`：系统付款候选，含可提取的订单、卖家、买家与交易类型线索。
- `order_state_signal`：发货、退款、取消等候选状态变化。
- `outgoing_message_evidence`：与一次发送严格关联的接纳证据。
- `trace_gap` / `protocol_issue`：无法可靠处理的条目、追溯缺口和平台协议变化。

普通聊天不转换为付款事件。系统消息只是触发核验的信号，自动发货仍须具备第 4 节事实。
平台事件 ID 不存在时使用账号范围内的规范化事件指纹协助去重；订单交付唯一性由应用层
持久约束保证，不能只靠内存事件缓存。

同步帧按原始顺序处理所有条目：一条损坏或某账号处理失败不能丢弃同帧其他有效条目。
Base64/MessagePack 解析有大小、深度及条目数界限，兼容整数键与规范化编码。
平台 Push ACK 按原始帧发送一次并保留协议要求的完整关联头；ACK、单条解码、
业务持久化及交付成功是四个独立事实。

读泵和心跳不能被详情查询或发货等待阻塞。帧 ACK 不构成本地事务提交证明，
不能假设 ACK 后平台必然重放；入站持久化失败、队列溢出或断连必须记录同步缺口并进入
订单追溯。同步游标推进不得让失败的业务条目从恢复范围中消失。

## 4. 订单事实与完备性

`OrderSnapshot` 必须表达每项字段是已核验、缺失、冲突还是不支持；
总的 `complete_for_delivery` 只能由应用要求的所有必要事实共同满足，不能以 HTTP 200 推断。

| 事实 | 契约 |
| --- | --- |
| 订单身份 | 平台订单 ID、卖家 ID、买家 ID、所属账号一致；冲突优先于任何成功状态 |
| 商品身份 | 单个受支持商品及其归属；多商品组合订单首版不支持 |
| 交易类型 | 明确普通交易才进入本版自动处理；小刀/免拼、未知类型均不得当普通交易 |
| 当前状态 | 待付款、待发货、已发货、完成、退款中、退款成功、取消、未知；保留来源与观察时间 |
| 付款时间 | 可信 `paid_at` 和来源，来自明确付款字段或经证实语义的付款事件时间；不能用创建时间、接收时间或最近更新时间替代 |
| 实付金额 | 非负整数最小货币单位和币种，按字段语义解析十进制；不使用浮点数，不将缺失金额当零 |
| 数量 | 明确正整数；缺失不是默认 1，超界或含糊值为不完整 |
| 完整 SKU | 规范化键值集合；保留平台稳定 ID（如有）和展示名称，区分已证明无规格与规格未知 |
| 会话身份 | 发往当前订单买家且归属当前账号的已核验会话，不能取“最近聊天”作为默认 |
| 完备性 | 缺失字段、冲突字段、来源、观察时间、是否经浏览器补足和原始来源摘要 |

SKU 规范化不得丢维度，不按子集命中，不拼接未转义字符串作为唯一身份。键排序用于稳定比较，
重复键、矛盾值、缺少任一必需维度均拒绝完整匹配。商品规格定义只能辅助核验，不能替订单
猜买家选择；DOM 模糊文本不得提升为精确 SKU。

监控范围比较可信 `paid_at` 与账号首次监控生效时间。付款发生在监控前的历史订单仅展示；
缺 `paid_at` 的订单不能因“现在待发货”自动接管。应用层可通过逐单人工接管进入受控流程，
但不得伪造付款时间或绕过身份、状态与规格核验。

恢复或人工动作前查询新事实；不能用历史付款推送覆盖较新退款/取消事实。来源矛盾或
时间先后不确定时停止自动执行，生成待处理事项。普通自动交付只接受当前待发货；
显式补发是否允许已发货由应用层按需求判定，平台层仍完整返回当前状态。

## 5. 商品全量同步与订单追溯

商品页成功但省略 `cardList` 按正常空页处理；明确返回错误类型或失败状态则不是空页。
全量结果含同步 ID、起止时间、页数、终止原因、是否完整；只有完整同步才能让应用层
将未出现的商品标记下架。部分失败保留已知商品事实，不返回伪造的完整空结果。

订单追溯输出 `requested_range`、`observed_range`、`coverage_complete`、最后游标、
终止原因与 `gaps`。平台列表可能按创建时间而非付款时间排序，必须以实际接口语义规划
分页范围；不能在遇到一笔创建于监控前的订单时结束付款范围追溯。

出现平台历史保留限制、页数预算耗尽、页重复、跳页、时间缺失、限流或部分解析失败时，
报告可审计缺口，不能宣称“无漏单”。候选订单须再拉详情核验；追溯结果本身不调用发货。
恢复目标是需求指定可完整追溯区间，不承诺找回平台已不可查询的订单。

## 6. 文本提交、证明与取消边界

发送输入必须使用已保存的不可变正文及其版本/摘要，保留中文、换行和原链接，不截断、
不拆分。首版产品限制为 1000 Unicode 标量且 UTF-8 不超过 4000 字节；若实证平台限制更低，
适配器报告较低能力限制，保存和执行前均拒绝超限。这不是已证明的平台上限。

结果是下列互斥变体：

| 结果 | 必要证据 | 应用含义 |
| --- | --- | --- |
| `not_submitted` | 参数校验、取消或传输状态证明没有进入不可收回的提交阶段 | 仅暂时故障可能按既定预算重试原内容 |
| `rejected` | 与当前请求关联的平台明确拒绝；附安全错误码 | 永久拒绝转待处理，不无限重试 |
| `accepted` | 当前请求 ID、账号、买家、会话、正文及平台消息标识匹配的可核验响应或回显 | 记录平台已接纳，不代表买家已阅读或下载 |
| `unknown` | 可能已提交，但缺完整可靠证据 | 保留原内容与尝试，禁止自动重发和自动确认发货 |

socket 写成功、裸 HTTP/WS 200、一般心跳 ACK 和相同正文的任意历史消息均不构成 `accepted`。
登记等待器必须先于写出请求；mid、平台消息 ID 及账号代次共同约束关联。迟到回显不能
确认后一次同文发送；重复平台证据不能被消费多次。无法严格关联的回显保留待核对，不靠
“最近一条内容相同”推断成功。关联 ID 用于证据，不宣称平台支持幂等重放或网络恰好一次。

应用先提交正文快照、请求关联 ID 和 `dispatching` 尝试，再请求账号执行器 handoff。
最终 handoff 前检查控制代次、凭证代次、规则版本、账号开关与恢复隔离。暂停屏障与
handoff 在同一账号执行器中串行化：屏障前已交出的动作只跟踪结果；屏障后不得发起新动作。
暂停请求到屏障完成之间状态为“暂停处理中”。取消调用不能撤销平台已经收到的请求。

进程在 `dispatching` 后退出且没有保存确定结果，恢复视为 `unknown`；
即使事后猜测尚未写 socket，也不能据此自动重发。取消后的实际响应仍须关联并记录，
不能因为界面请求断开而丢弃已提交动作的结果。自动重试预算由应用保存，适配器不得
在一次 `send_text` 内偷偷多次提交。

## 7. 凭证代次与官方验证/浏览器桥接

扫码会话有短期 ID、到期时间、原临时 Cookie Jar 与取消状态。取消/到期后迟到成功
不能覆盖新会话；重新授权必须核验为预期账号，身份变化需应用显式处理。
凭证包含作用域、路径、到期时间、HttpOnly/Secure 等属性；签名所需 Cookie 与请求 Cookie
应按实际 URL 选取，不能把同名不同域 Cookie 展平成一个值。

凭证更新返回原 `credential_generation` 及增量/权威快照性质。只有当前代次可合并；
旧授权、旧浏览器或旧续期结果不得覆盖新授权。Token 过期可受控重新签名只读请求，
登录失效转续期或重新扫码；业务动作能否重试取决于提交证据，不取决于拿到新 Token。

需要官方验证时暂停账号新外部业务动作，保存受保护的短期验证会话。首选官方支持的
扫码/手机交互；需要浏览器时使用 chromiumoxide 控制本机兼容 Edge/Chrome 的专用受限
profile，延续原授权会话。不得读取用户日常 profile、执行自动滑块或绕过验证。
导航、跳转、Cookie 导入导出和验证完成均需要允许的官方域及身份核验；未经验证的 URL
不能当成任意浏览器导航能力暴露。临时调试端点仅本机受控使用，不开放给网络访问。

浏览器按需启动，用于官方交互验证或 MTOP 无法提供必要金额/规格时的详情补足。
由独立管理器拥有进程、profile、CDP 连接和清理生命周期；账号隔离，数量有界，
退出/取消后清理自己创建的进程，不结束用户已有浏览器。缺浏览器返回明确不可用及操作提示。
浏览器同样只输出带来源的事实或验证结果，不直接匹配规则、发正文或改业务记录。

验证“完成”必须依赖新的可用授权及账号身份事实，不以窗口关闭或页面标题判断。
旧浏览器 Cookie 不能回写新代次；浏览器响应和 DOM 仍不满足完整事实时转人工处理。
需要浏览器的目标账号不能被标为“已验证可无浏览器运行”。

## 8. 平台确认的独立契约

`confirm_shipment` 只接受应用层授予的独立执行资格和保存的原内容交付证明。
自动确认开关关闭不影响正文发送；正文未知不允许自动确认。人工标记“买家已收到”
不自动触发平台确认，须管理员另选独立操作并重新核验。

确认结果分别为未提交、明确拒绝、明确成功和未知，保留独立请求关联与证据。
明确成功需匹配当前订单的业务成功语义；裸传输成功不足够。超时可只读核验当前订单状态，
核验结果标注来源和时间，不能伪造为原请求响应。已发货状态不能反向证明正文已收到。
确认失败、未知或重试绝不调用 `send_text`；请求不确定时不靠重复确认掩盖未知事实。

## 9. 支持声明与实现门禁

首版只开放闲鱼普通单商品固定文字交付。小刀/免拼、卡密、按件独立权益、淘宝千牛及
其他平台明确返回不支持，不生成伪成功任务，不以通用适配器占位实现宣称可用。

确定性验收至少包括：扫码重定向和 Cookie 作用域、凭证换代竞态、多条推送夹坏条目、
重复/乱序事件、退款覆盖、完整 SKU/缺金额/缺数量/缺 paid_at、商品空页/不完整同步、
分页缺口、发送裸 200/完整证明/断连/迟到回显、暂停 handoff 竞争、确认未知和浏览器不可用。
浏览器夹具使用本地页面验证会话隔离和取消，不需要真实凭证。

发布前另须明确授权的实账号证据：扫码及所遇官方验证、普通付款交付、多规格、文本边界、
可靠发送证明、确认开关和人工补发，并记录版本/日期与追溯范围。任何缺证项目保持
待验证状态；本设计文档不代替真实平台兼容性或性能测试。
