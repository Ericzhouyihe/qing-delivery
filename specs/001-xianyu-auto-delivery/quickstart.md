# Quickstart & Validation: 轻交付首版

**阶段声明**：这是后续实施的运行与验收指南；当前仓库只有规划文档，没有以下应用命令、
脚本或测试实现。不能把本页命令视为已经执行通过。此轮没有安装工具链、启动平台或发真实消息。

技术决策见 [research.md](research.md)，状态及恢复规则见 [data-model.md](data-model.md)，
接口见 [HTTP](contracts/http-api.md)、[CLI](contracts/cli.md) 和 [平台契约](contracts/platform-adapter.md)。

## 1. 开发前提

- 原生 Windows 11 x64，Rust stable（至少1.85并满足依赖MSRV）、MSVC构建工具。
  首次兼容实验后提交 `rust-toolchain.toml` 与 Cargo.lock，后续按锁定版本验证。
- Node 24 LTS 与 npm；前端锁定依赖。卖家发行版不需要上述开发工具。
- 当前用户有可写的本地NTFS数据目录，非网络共享/同步盘；数据目录权限限制当前用户。
- 本地测试不需要真实闲鱼账号。页面测试浏览器由开发依赖安装；平台浏览器兜底使用
  明确配置的兼容Edge/Chrome，专用profile，不访问现有日常浏览器资料。
- 真实平台验收前另取得对应账号与有限测试交易的明确授权，不默认读取已有Cookie或库存。

## 2. 实施时必须建立的命令约定

以下均在仓库根目录的PowerShell执行；前提是实现阶段已创建对应源码、npm scripts和锁文件。

```powershell
rustc --version
cargo --version
node --version
npm --version
npm ci --prefix frontend
npm run typecheck --prefix frontend
npm run test --prefix frontend -- --run
npm run build --prefix frontend
cargo fmt --all -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked --all-targets
cargo build --locked --release
```

前端build输出到后端嵌入目录。CI/release严格要求已构建产物，不能静默使用上一次页面。
每条命令非零退出都阻止发布；测试报告必须证明本次关键测试实际运行，不能因过滤后零测试而通过。
Rust组合构建未验证前不得声称发布资源预算或二进制尺寸。

## 3. 本地运行与初始化

```powershell
cargo run --locked -- serve --data-dir .work/dev-data --bind 127.0.0.1:59189
```

浏览器打开 `http://127.0.0.1:59189`。设置两次一致、至少12字符的管理员密码。
密码不写命令参数/示例日志。首次无账号时显示空状态，不自动连接闲鱼。
健康检查只返回状态与版本，不返回账号或敏感数据。

```powershell
Invoke-RestMethod -Uri 'http://127.0.0.1:59189/health'
```

开发页面可在另一终端 `npm run dev --prefix frontend`，由Vite代理本地后端；不设置任意来源CORS。
本机Host/Origin/CSRF校验按契约配置开发代理地址，不能以关闭校验解决开发连通问题。
正式数据默认 `%LOCALAPPDATA%\QingDelivery\data`；测试始终使用独立临时目录。

## 4. 可控场景环境

实现阶段提供仅开发构建的 `dev-fixtures` 功能，页面演示使用进程内模拟适配器及合成账号，
协议集成测试另外启动本地HTTP/WS假服务以验证真实编码和网络边界；两者不能互相替代。
不能在发行版中开启，不使用真实域名、真实Cookie或生产数据目录。

```powershell
cargo run --locked --features dev-fixtures -- serve --profile mock --data-dir .work/mock-data --bind 127.0.0.1:59190
```

mock配置须拒绝非回环外部平台目标，数据目录写入mock标记；正式serve拒绝该标记目录。
故障注入由集成测试/本地夹具驱动，不提供发行版后门HTTP接口。
样本包含3个虚构账号、100商品、10k历史订单、完整/缺失SKU、普通/小刀/退款等事实。
详细负载由测试夹具固定，测试启动不得复制参考项目中的原始业务数据库。

## 6. 备份恢复验证步骤

服务停止后再执行首版CLI备份，所有命令对临时测试目录操作。
使用 online backup API 是一致快照技术，不表示CLI需要支持服务运行中备份。

```powershell
# 先在服务终端正常停止并确认目录锁已释放
.\target\release\qing-delivery.exe backup --data-dir .work/dev-data --output .work/backup.qdbak
# 恢复必须停机；归档解密限制同机器同Windows用户
.\target\release\qing-delivery.exe restore --data-dir .work/restore-data --input .work/backup.qdbak
.\target\release\qing-delivery.exe serve --data-dir .work/restore-data --bind 127.0.0.1:59191
```

对已有目标数据目录，restore必须按CLI契约明确确认替换并保留原副本；不要用删除目录简化流程。
验收对比业务配置、规则、历史正文与去重记录；暂停位、会话撤销、恢复隔离是有意变更，不应要求相同。
恢复后即使手动启用账号，备份期间及备份中未完成任务仍不能自动重发。
以明确新付款事件证明恢复完成以后的新订单可以在重新启用后正常处理。

## 7. 性能与可靠性记录

固定操作系统、CPU、内存、构建版本、浏览器版本与3账号样本集。
记录5分钟配置过程、100笔正常交付和10k订单查询的样本数/分位数；任何排除样本列明原因。
分别记录服务与浏览器进程峰值/空闲内存、CPU、冷启动和页面加载，不能只测Rust主进程。

付款时间、通知接收、事实齐全、准备提交、平台确认和持久保存时间分别记录，
性能日志只保留非敏感关联ID；不要把平台等待算成本地代码执行，也不要排除慢样本来美化P95。
真实异常/失效次数、手工介入数及未知结果数和成功率一起报告。

## 8. 发布前真实平台矩阵

每项至少一份明确授权的证据：扫码与账号身份、普通付款、完整多SKU、
自动平台确认开/关、原内容人工补发。记录日期、客户端/协议环境、应用提交、结果及待验证项。
凭证和完整买家数据不得进入仓库，证据使用脱敏编号。

另外核对文本边界、订单追溯范围、消息接纳证明、是否需要浏览器兜底。
若协议不能给出完整SKU且浏览器兜底尚未可用，不得宣称“完整规格首版已完成”。
未具备实账号条件时，其余测试继续执行，但版本标记为待验证，不以模拟成功替代SC-009。
