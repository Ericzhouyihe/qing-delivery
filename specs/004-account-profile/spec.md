# Feature Specification: 账号资料同步与管理增强(004-account-profile)

**Feature Branch**: `004-account-profile`

**Created**: 2026-09-25

**Status**: Draft

**Input**: User description: 对比参考项目账号管理页,当前账号卡存在 4 个差距——①头像没有同步(占位字);②昵称没有同步(显示兜底"闲鱼账号+ID");③平台 ID 不必脱敏显示;④没有办法删除账号。参考:Ydisks 的"刷新资料/删除/备注"交互。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 账号资料同步:昵称与头像 (Priority: P1)

卖家扫码接入后,系统自动从平台拉取该账号的资料(昵称、头像),账号卡显示真实昵称与头像图,不再是"闲鱼账号+数字 ID"兜底;账号卡提供"刷新资料"动作,资料变更(改名/换头像)后可手动重新拉取;授权完成时的首次拉取自动执行,失败不阻塞接入(显示兜底 + 可重试)。

**Why this priority**: 多账号卖家靠昵称/头像区分账号;兜底名"闲鱼账号 3996…"无法辨识,是接入后第一眼缺陷。

**Independent Test**: 用真实账号接入或点击"刷新资料",账号卡在数秒内显示真实昵称与头像。

**Acceptance Scenarios**:

1. **Given** 扫码授权完成, **When** 账号建立, **Then** 系统自动拉取一次资料;成功后账号卡显示真实昵称与头像;失败时保持兜底名并在账号卡提供重试入口,不阻塞接入流程。
2. **Given** 账号卡显示兜底名或旧昵称, **When** 卖家点击"刷新资料", **Then** 数秒内完成拉取并更新昵称与头像;拉取期间按钮呈进行态。
3. **Given** 平台返回的资料不含头像或拉取失败, **When** 渲染账号卡, **Then** 头像位回退为现有首字占位,不显示破图。
4. **Given** 资料拉取成功且平台在响应中下发了更新后的 Cookie, **Then** 系统按既有凭证路径保存更新(与参考项目行为一致)。

---

### User Story 2 - 删除账号 (Priority: P1)

卖家可删除不再使用的账号:删除走破坏性确认流(说明后果);删除后该账号停止值守、加密凭证一并清除(敏感数据不留存),账号从账号页消失;**历史订单与交付审计记录保留**(可追溯),订单页历史行照常可查。

**Why this priority**: 接错的账号/换绑的账号没有退出途径,只能停用不能移除,敏感凭证长期留存违背后期数据卫生诉求。

**Independent Test**: 对一个测试账号执行删除,确认:值守停止、凭证行清除、账号列表消失、订单历史仍可查。

**Acceptance Scenarios**:

1. **Given** 账号处于任意状态, **When** 卖家点击删除并完成确认流(输入账号备注/ID 片段确认), **Then** 值守任务停止、加密凭证删除、账号从列表消失;全程不影响其他账号。
2. **Given** 账号有历史订单, **When** 删除完成, **Then** 订单/交付审计数据完整保留,订单中心历史行仍显示该账号(以 ID 呈现)。
3. **Given** 删除确认流, **When** 卖家取消, **Then** 无任何变更。
4. **Given** 删除请求到达但账号仍有进行中的验证/交付处置, **Then** 系统先安全停止处置再删除,不产生半途状态。

---

### User Story 3 - 平台 ID 明示与账号备注 (Priority: P2)

账号卡完整显示平台用户 ID(不再脱敏截断),并支持卖家为账号填写备注(如"主号/福利号"),备注显示在昵称下方;多账号区分不再依赖数字。

**Why this priority**: 用户明确"ID 不用隐藏";备注是参考项目验证过的多账号辨识手段,成本低。

**Independent Test**: 账号卡显示完整 ID;编辑备注后保存,刷新仍在。

**Acceptance Scenarios**:

1. **Given** 账号卡渲染, **When** 查看账号信息, **Then** 平台 ID 完整显示(可一键复制)。
2. **Given** 卖家编辑备注并保存, **When** 返回账号页或刷新, **Then** 备注持久显示在昵称下方。

---

### Edge Cases

- 资料拉取遇风控(平台要求验证):按 003 管道转安全验证处置,资料失败原因如实展示,不静默重试。
- 删除时账号正在验证处置中:先等待/停止处置(有上限)再删除。
- 头像 URL 失效或平台防盗链:界面回退首字占位,不反复重试拉图。
- 删除后同平台同 ID 重新扫码接入:视为新账号建立(新本地账号),不复活旧数据。
- 备注为空:显示"暂无备注"弱化文案(参考项目同款)。
- 删除是终局操作:确认流必须明确"凭证将被清除、不可恢复;订单历史保留"。

## Requirements *(mandatory)*

### Functional Requirements

**资料同步**

- **FR-001**: 授权完成后系统 MUST 自动拉取一次账号资料(昵称、头像 URL);失败不阻塞接入且提供手动重试。
- **FR-002**: 账号卡 MUST 提供"刷新资料"动作,拉取期间进行态、结果即时反映(昵称/头像/失败原因)。
- **FR-003**: 头像 MUST 以图片呈现;不可用时回退首字占位,不显示破图。
- **FR-004**: 资料拉取响应若携带更新后的平台 Cookie,系统 MUST 按既有加密凭证路径保存(与参考项目一致)。
- **FR-005**: 资料拉取遇平台风控信号时 MUST 转入 003 安全验证处置管道,不自行重试。

**删除账号**

- **FR-006**: 系统 MUST 提供删除账号能力:停止值守→清除加密凭证→账号从列表移除;全过程走破坏性确认流(FR-005 模式)。
- **FR-007**: 删除 MUST 保留历史订单与交付审计数据(可追溯性优先于存储节省);订单中心历史行的账号以 ID 呈现。
- **FR-008**: 删除前 MUST 完成在途处置的安全收尾(验证/交付有上限等待)。
- **FR-009**: 删除后同平台同 ID 重新接入 MUST 视为新账号,不自动关联旧数据。

**ID 与备注**

- **FR-010**: 账号卡 MUST 完整显示平台用户 ID 并支持一键复制。
- **FR-011**: 卖家 MUST 可为账号设置/修改备注,备注持久化并显示于昵称下方。

### Key Entities *(include if feature involves data)*

- **账号资料(AccountProfile)**: 昵称、头像 URL、平台用户 ID、备注;昵称/头像来自平台同步,备注来自卖家输入。
- **删除语义(AccountRemoval)**: 软移除——接入态(凭证/值守/列表可见性)清除,审计态(订单/交付/事项历史)保留;删除后 ID 可重新接入为新账号。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-401**: 实账号接入后 30 秒内账号卡显示真实昵称与头像(或明确失败原因+重试入口);刷新资料 ≤5 秒完成。
- **SC-402**: 删除账号后:值守任务 0 残留、凭证行 0 残留(数据库核验)、订单历史完好可查。
- **SC-403**: 账号卡显示完整平台 ID,一键复制可用;备注保存后跨会话持久。
- **SC-404**: 回归基线:现有测试(前端 80+80 / Rust 146)全部保持通过;契约全部 additive。

## Assumptions

- 平台资料接口(用户信息查询)按参考项目流程经 mtop 实现,响应字段(昵称/头像 URL 字段名)以实账号观察校准(R11 模式),不臆造。
- 头像直接引用平台 URL(不下载落盘);防盗链或失效时回退首字占位。
- 删除采用软移除语义(接入态清除+审计保留),不物理删除订单数据——宪章 I 可追溯优先。
- 参考项目的"备注"交互仅作呈现参照;本项目备注为本地字段,不同步回平台。
