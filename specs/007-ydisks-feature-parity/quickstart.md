# Quickstart: 007-ydisks-feature-parity 验证指南

按七个增量(US1~US7)组织的端到端验证。每增量可独立验收;增量内步骤按顺序执行。契约细节见 [contracts/http-api.md](contracts/http-api.md),表结构与状态机见 [data-model.md](data-model.md)。

## 前置准备(每个增量通用)

```powershell
# 1. 前端构建产物(被 Rust 二进制嵌入,改前端后必须重建)
cd frontend; npm install; npm run build; cd ..

# 2. 后端(演示档需要 dev-fixtures feature)
cargo build --features dev-fixtures

# 3. 干净数据目录 + 播种演示样本
mkdir target\demo-007
target\debug\seed-ui.exe target\demo-007

# 4. 启动(mock 执行档,真实协议不外呼)
target\debug\qing-delivery.exe serve --profile mock --data-dir target\demo-007
# 浏览器打开 http://127.0.0.1:59189,首次进入创建管理员
```

回归基线:启动后概览/账号/商品/订单/待处理/设置六页可正常打开(002/005/006 能力零回退);`cargo test` 与 `npm run test` 全绿(迁移测试的表数量断言已更新为 44)。

## US1 卡密库存

1. 导航出现"卡密库存",打开显示"暂无卡密配置"空态。
2. "添加新卡密" → 类型选"批量库存",粘贴 3 行卡密保存 → 列表显示"库存: 3 条",内容无明文回显。
3. 用"批量导入"上传 CSV(先下载模板)→ 结果报告逐行成功/失败,仅成功行入库。
4. 商品与规则页(或新"自动化规则"页)为某商品建付款发货规则,内容来源选该卡密组,每件份数 1。
5. 触发一笔已付款订单(mock 档经演示流程或 `POST /api/v1/dev/scenarios/.../runs`)→ 订单详情:交付 accepted;卡密组余量 3→2;条目列表中该卡状态 `used` 且绑定订单号。
6. 断网/停池场景:把组停用后再触发 → 订单转待处理,kind=`stock_insufficient`,不做部分交付。
7. 删除被规则引用的组 → 409 `referenced_resource` 提示;规则页该规则显示"需重新配置"。
8. 概览第 5 张卡"库存卡密余量"= 全部启用批量组可用余量之和,随交付实时变化。

## US2 发货模板

1. "发货模板"页新建模板:两条消息,分别含 `{{buyer_nickname}}` 与 `{{cards.key1}}` → 保存成功,变量指南可见。
2. 故意输入 `{{cards.非 法}}` → 保存被拒并指出错误位置。
3. 在规则中选择该模板并绑定 `key1` 到卡密组;`{{custom.备注}}` 未赋值 → 保存被拒。
4. 触发订单 → 买家按顺序收到两条消息;订单详情尝试记录中每条消息各有一行 proof。
5. 预览端点返回的 `rendered_messages` 与实际发送内容一致(卡密内容掩码显示)。
6. 删除被引用模板 → 409;解除引用后可删。

## US3 自动化规则扩展

1. 导航"自动化规则"独立页(原"商品与规则"拆分):三页签齐全;商品列表页"关联发货规则"可跳转并定位。
2. 同一多规格商品建一条规则、两个变体(规格 A→卡组 1、规格 B→卡组 2)→ 分别触发两种规格订单,各自命中正确卡组,取卡数=份数×件数。
3. 同范围同触发建第二条规则、不同优先级 → 仅优先级数字最小者执行;同优先级再建 → 422 `rule_conflict`。
4. 账号级规则未勾选"适用于全部商品" → 触发订单不发货,规则卡显示"需确认·暂不发货";勾选确认后正常执行。
5. 关键词回复页签:配"包含'套餐'→回复文字" → 买家消息命中自动回复,订单与交付状态零变化。
6. 默认回复页签:启用+只回复一次 → 同会话第二条普通消息不再回复;"清空记录"后恢复回复。
7. 求评规则(等待 0.01h 测试)→ 已交付订单到期收到求评文案,次数达上限停止;账号停用期间跳过并留痕。
8. 执行失败(停用卡组)→ 待处理页出现事项,allowed_actions 只含该结果允许的操作,处置留痕。

## US4 在线聊天

1. 导航"在线聊天"带未读徽标;页内账号 Tab、会话列表、消息面板三栏呈现。
2. 模拟买家来消息(mock 档)→ 会话未读 +1、侧边栏徽标更新;打开会话未读清零。
3. 发送文本(回车)→ 状态"发送中→已发送";超 2000 字被拒。
4. 制造 Unknown 结果 → 消息标黄"结果未知",无自动重发;failed 消息可手动重试,uncertain 重试按钮禁用并说明。
5. 快捷回复抽屉:新增/复制/发送/删除;第 51 条被拒(`reply_limit_reached`)。
6. 买家备注:查看/编辑/保存;非卖家角色会话不显示入口。
7. 删除会话 → 确认后本机隐藏;图片入口与历史说明按 capabilities 如实(未声明时隐藏图片、提示"仅展示接入后收到的会话")。

## US5 通知渠道

1. "通知设置"页新建 Webhook 渠道(接收端可用任意本地 HTTP 收集器)→ 测试成功,接收端收到消息。
2. 编辑渠道 → secrets 显示"已配置"占位;留空保存不覆盖;钉钉加签错误 → 测试返回结构化失败原因。
3. 仅订阅"账号掉线" → 制造掉线事件触达,交付结果事件不发送。
4. 账号绑定渠道后仅向绑定渠道发送;未绑定账号走全部启用渠道。
5. 制造 unknown 投递 → `notification_deliveries` 留痕 + 待处理出现 `notify_unknown`。
6. 管理员配置系统 SMTP,邮件渠道选"使用系统 SMTP"发信成功。

## US6 订单同步与人工交付动作

1. 订单页"一键同步" → 202 任务轮询进度;完成显示逐账号 `created/restored/reassigned/ineligible/failed`;可中途取消。
2. 离线账号跳过并标注;单笔同步按钮返回该订单 HandleOutcome。
3. 待交付订单"人工触发交付" → 走完整管线;重复点击幂等拒绝;留痕于人工动作审计。
4. 缺付款事实的订单 → 按钮禁用并指明缺失要素。
5. 已交付订单"人工确认平台已发货" → 平台确认轴独立更新,消息交付记录不变,原因留痕。

## US7 系统与AI

1. "系统与AI"页:AI 配置表单;填入 OpenAI 兼容地址+Key → "读取模型"返回列表,"测试连接"返回模型/耗时/回复摘要。
2. Key 已配置后重进页面 → 占位显示,不回显明文。
3. 账号 AI 开关+提示词 → 买家普通消息(关键词未命中)收到 AI 回复;订单/交付零变化;AI 地址改错 → 静默降级且留痕可查。
4. 分流顺序:关键词命中时不调 AI;AI 关闭时默认回复兜底。
5. 修改管理员密码:当前密码错误 → 422;成功后另一会话回落登录,新密码可登录,旧密码失效。
