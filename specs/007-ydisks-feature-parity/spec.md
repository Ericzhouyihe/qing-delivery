# Feature Specification: Ydisks 功能缺口复刻·多域增量(007-ydisks-feature-parity)

**Feature Branch**: `007-ydisks-feature-parity`

**Created**: 2026-09-25

**Status**: Draft

**Input**: User description: "跟Ydisks的前端复刻的功能缺少了很多啊,你继续分析一下Ydisks的源码,可以根据他的前端页面抽离业务,然后进行代码复刻,编写的代码需要符合ddd领域驱动,方便不断迭代增加功能"。参考截图为 Ydisks 闲鱼助手"运营概览"页:侧边栏完整导航为 仪表盘、账号管理、在线聊天、卡密库存、商品列表、订单管理、发货模板、自动化规则、通知设置、系统与AI(共 10 项),另含运行版本、收起侧边栏、退出登录。

经对 Ydisks 源码(`Ydisks-Xianyu-Helper/`,前端 12 个 feature 目录 + openapi.yaml)与本项目现有实现(specs 001~006)的差距走查,确认以下缺口:

- **整页缺失**:在线聊天、卡密库存、发货模板、通知设置(Ydisks 有完整页面,本项目无对应功能)。
- **部分缺失**:自动化规则仅有"单一内容规则"模型,缺多触发类型、多规格变体、优先级、关键词回复、账号默认回复;订单缺一键同步/单笔同步/人工触发交付/人工确认平台发货;设置页只读,缺 AI 配置与管理员凭据修改;概览缺"库存卡密余量"统计卡;侧边栏缺"商品列表/自动化规则"独立入口(现合并为"商品与规则")。
- **架构要求**:所有新增能力按领域驱动分层(领域规则 / 应用用例 / 端口适配 / 交互传输)组织,每个能力域是可独立迭代的限界上下文。

## Clarifications

### Session 2026-09-25

- Q: 买家消息的自动回复分流顺序是什么?→ A: 关键词匹配(商品级关键词优先于账号级)→ AI 回复(账号开启时)→ 账号默认回复兜底,命中即止,任一环节失败顺延下一环节。(源码证据:Ydisks `internal/engine/reply.go` 的 `resolve()` 优先级链;其"API 回复"环节属外部集成,不在本项目范围)
- Q: 同一账号同一商品同一触发允许多条启用规则并存时如何执行?→ A: 允许多条并存,仅执行优先级数字最小(最高)的一条;同范围同触发同优先级的重复规则拒绝保存。001 规格"同范围仅一条启用规则"的约束相应修订为该优先级模型。(决策:采纳"多条规则+优先级"推荐项——复刻 Ydisks 行为所必需;宪章防重复交付由"仅执行最高一条+既有执行互斥"保障)
- Q: 既有"固定内容规则"(001/002 已实现的加密固定文字)如何处置?→ A: 并存零迁移——固定内容继续作为与卡密组、发货模板并列的一种内容来源,存量数据零迁移,既有页面行为不回退。(决策:采纳"并存零迁移"推荐项——迁移收益低于风险,契合增量迭代目标)
- Q: 订单"一键同步"采用什么对账语义?→ A: 按账号全量对账(新增/恢复/修正),复用既有事件摄取与漏单补偿逻辑;离线账号跳过并在结果中注明。(源码证据:Ydisks 订单刷新任务结果含 restored/reassigned 全量修正语义)
- Q: 卡密在交付流程中何时固定内容?→ A: 预留时即取卡,内容加密快照并绑定订单,后续发送使用该快照;结果未知不回库。(宪章"对外发送前必须持久化内容"的直接落实)
- Q: 求评计划多久扫描一次?→ A: 默认每小时扫描一次已交付订单,账号停用/离线时跳过并留痕。(合理默认,Ydisks 为计划任务扫描)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 卡密库存域(库存组与订单绑定交付) (Priority: P1)

卖家打开"卡密库存"页,创建/管理四类卡密组:批量库存(一行一张卡,实时显示余量)、固定文本、图片链接、API 取卡(URL/方法/超时/请求头/参数/请求体/响应取值路径,可一次性"测试"且不保存)。支持粘贴追加库存、按表格文件批量导入(逐行成功/失败报告)、组级延时发货与启停、按类型与名称筛选。规则命中后系统从对应卡密组原子预留一张卡绑定订单,发送成功后完成扣减;库存余量同步反映在概览页新增的"库存卡密余量"统计卡。

**Why this priority**: 卡密库存是虚拟商品交付内容的根基——发货模板的卡密变量、自动化规则的发货动作都引用它;没有库存池,后续域无从谈起。

**Independent Test**: 创建一个批量库存组并导入 3 张卡,配到规则后模拟一笔已付款订单,验证预留→发送→扣减全链路,余量从 3 变 2;删除组需确认且被引用时受保护。

**Acceptance Scenarios**:

1. **Given** 无任何卡密组, **When** 打开卡密库存页, **Then** 显示"暂无卡密配置"空态与"批量导入/添加新卡密"入口。
2. **Given** 创建类型为"批量库存"的组并粘贴 3 行卡密, **When** 保存, **Then** 列表该组显示"库存: 3 条",内容不以明文回显。
3. **Given** 一张已预留绑定订单的卡, **When** 查看组详情, **Then** 该卡标记为预留且关联订单,余量计数不含它。
4. **Given** 发送确定成功, **When** 扣减完成, **Then** 卡状态为已使用,不可再次分配;同一订单不得获取第二张卡。
5. **Given** 一条被自动化规则引用的卡密组, **When** 卖家点击删除, **Then** 系统提示引用关系并要求显式确认,确认前不删除。
6. **Given** 概览页, **When** 卡密组存在, **Then** 显示"库存卡密余量"统计卡,数值等于全部启用批量组可用余量之和。

### User Story 2 - 发货模板域(多消息模板与变量) (Priority: P2)

卖家在"发货模板"页创建模板:名称、启用开关、自上而下的有序消息列表(至少一条,可增删),消息中可插入变量占位符(买家昵称、订单号、买家 ID、卡密组名、卡密变量、自定义变量);编辑器右侧提供变量指南与示例。保存时系统校验变量拼写与消息非空。模板在自动化规则中被选择后,规则内可把模板的卡密变量逐个绑定到卡密库存组并填写自定义变量取值。被规则引用的模板不可删除。

**Why this priority**: 模板把"发什么"从规则里解耦出来,是规则域(US3)发货动作的载体;依赖 US1 的卡密组提供变量来源。

**Independent Test**: 创建含 `{{buyer_nickname}}` 与卡密变量的两条消息模板,在规则中绑定卡组后触发一笔订单,发送内容与变量渲染预览完全一致。

**Acceptance Scenarios**:

1. **Given** 打开新建模板, **When** 只填名称不留任何消息, **Then** 保存被拒绝并提示至少一条非空消息。
2. **Given** 消息中输入 `{{cards.卡密变量}}` 且变量名含非法字符, **When** 保存, **Then** 系统指出拼写/命名错误位置,拒绝保存。
3. **Given** 模板含三条有序消息, **When** 触发交付, **Then** 按顺序逐条发送,每条为一则独立消息。
4. **Given** 模板已被某规则引用, **When** 删除该模板, **Then** 操作被拒绝并提示"被自动化规则引用的模板无法删除"。
5. **Given** 同一模板, **When** 两笔订单使用, **Then** 各自按订单事实渲染变量,互不影响。

### User Story 3 - 自动化规则扩展(变体/优先级/关键词/默认回复) (Priority: P3)

卖家在"自动化规则"独立页管理三类规则:

- **交易自动化**:在既有"付款自动发货"基础上增加多规格变体(规格名/规格值对应不同卡组或模板、每件份数、延时覆盖)、优先级(数字越小越高,同范围同触发仅执行最高一条)、账号级规则需显式确认"适用于全部商品"后方可生效;新增"超时未评价求评"计划规则(发货后等待小时数、再次求评间隔、最多次数、求评文案)。"评价后发送赠品"仅在平台适配器声明已验证评价事件能力后可用,未验证时入口隐藏。
- **关键词回复**:针对买家消息(不触发发货)配置"包含关键词→回复文字/图片",可关联多个商品或不关联(账号级),支持同会话只回复一次。
- **账号默认回复**:每账号一段兜底回复文案,支持只回复一次与清空回复记录。
- 规则执行出现失败或结果未知时,事项进入既有"待处理"体系,按允许的操作(安全重试/继续/终止)处置,全过程可追溯。

**Why this priority**: 规则是把库存与模板串成自动发货业务的执行中枢,扩展后才能覆盖多规格商品与客服场景;依赖 US1/US2。

**Independent Test**: 为同一多规格商品配置两条不同规格变体的付款发货规则,分别模拟两种规格的已付款订单,各自命中正确变体并按份数取卡;构造两条规则同范围冲突,验证仅优先级最高者执行。

**Acceptance Scenarios**:

1. **Given** 多规格商品与含两个变体的规则, **When** 分别下单两种规格, **Then** 各按对应规格值匹配变体,取卡数量=每件份数×购买件数。
2. **Given** 同一账号同一商品存在两条启用的付款发货规则, **When** 订单触发, **Then** 仅优先级数字最小(最高)的一条执行,另一条不重复发货。
3. **Given** 账号级规则未完成"适用于全部商品"确认, **When** 保存并触发订单, **Then** 规则标记"需确认·暂不发货",不产生任何交付。
4. **Given** 买家发来含关键词"套餐"的消息, **When** 关键词回复规则命中, **Then** 自动回复配置内容,但不产生发货、不改订单状态。
5. **Given** 账号默认回复开启且"只回复一次", **When** 同一买家会话发来第二条无关键词消息, **Then** 不再重复回复。
6. **Given** 已发货订单超过配置等待小时仍未评价, **When** 求评计划执行, **Then** 发送求评文案,达到次数上限后停止。
7. **Given** 一次发货执行失败, **When** 打开待处理页, **Then** 出现对应事项,仅显示该失败结果允许的处置操作,处置留痕。

### User Story 4 - 在线聊天域(会话/消息/快捷回复) (Priority: P4)

卖家打开"在线聊天"页:顶部为账号 Tab(带在线状态与未读徽标);左侧会话列表(按账号,支持按用户/商品/消息搜索、"只看未读"切换、加载更多);右侧消息面板展示历史消息(文本、图片、系统通知、商品卡片样式),支持"加载更早消息"游标;底部输入区发送文本(限 2000 字,回车发送)与图片(≤10MB,支持粘贴预览后确认);右侧快捷回复抽屉(上限 50 条,可复制/发送/删除/新增);仅卖家角色的会话可查看与编辑"买家备注"。删除会话仅在本机隐藏并清空展示消息,不影响平台侧。离线账号输入区禁用并给出原因;外发消息显示发送中/已发送/失败(可重试)/结果未知(标黄警示、不可自动重试)四种状态。

**Why this priority**: 聊天是人工介入与客服的主战场,也是自动交付通道的可视化;文本收发能力已由交付管线验证,历史回填与图片发送依赖适配器能力声明,故排在内容链(US1-3)之后。

**Independent Test**: 选一在线账号给测试买家发送文本,验证消息出现在会话中且状态流转为已发送;发送超 2000 字被拒;删除会话后刷新不再显示。

**Acceptance Scenarios**:

1. **Given** 一账号有两会话其中一会话未读, **When** 打开聊天页, **Then** 对应账号 Tab 与会话项显示未读徽标,打开该会话后未读清零。
2. **Given** 在线账号, **When** 发送一条文本, **Then** 消息出现在面板,状态经"发送中"到"已发送";失败时显示红色失败标记与重试入口。
3. **Given** 发送结果未知(平台未确认), **When** 渲染该消息, **Then** 显示黄色"结果未知"警示,系统不自动重发,提示人工核对。
4. **Given** 快捷回复列表已 50 条, **When** 尝试新增, **Then** 被拒绝并提示上限。
5. **Given** 离线账号, **When** 查看消息面板, **Then** 输入区禁用并显示"账号离线"原因。
6. **Given** 历史会话回填能力未经适配器验证, **When** 打开聊天页, **Then** 页面如实说明仅展示接入后收到的会话,不虚构历史数据。

### User Story 5 - 通知渠道域(事件触达卖家) (Priority: P5)

卖家在"通知设置"页配置通知渠道:自定义 Webhook、邮件(独立 SMTP 或复用系统 SMTP)、钉钉机器人、飞书机器人、企业微信机器人、Bark、Telegram;每种类型提供配置字段与"如何获取配置"指引。渠道支持启用/停用、发送测试、编辑(秘密字段脱敏回显)、删除;可为每类事件选择订阅(账号掉线、账号恢复、需要人工处理、安全验证、交付结果、系统错误等,不选=全部);可按账号绑定渠道(覆盖式)。管理员可配置系统级 SMTP。通知发送全程持久化尝试与结果,结果未知转待处理。

**Why this priority**: 通知让卖家在关页时仍掌握账号与订单动态,是无人值守运营的保障;不依赖其他新域,可独立交付。

**Independent Test**: 配置一个 Webhook 渠道并点击"测试",在接收端收到一条测试消息;订阅"账号掉线"后制造掉线事件,验证触达且其他未订阅事件不发送。

**Acceptance Scenarios**:

1. **Given** 新建钉钉渠道并填写 webhook 与加签密钥, **When** 点击测试, **Then** 收到测试消息,页面显示成功;失败时显示具体原因。
2. **Given** 渠道已配置密钥, **When** 再次编辑, **Then** 密钥字段显示"已配置"占位而非明文,留空保存表示不修改。
3. **Given** 渠道仅订阅"账号掉线", **When** 发生"交付结果"类事件, **Then** 该渠道不发送。
4. **Given** 某账号绑定了指定渠道, **When** 该账号事件触发, **Then** 仅向绑定渠道发送;未绑定账号走全部启用渠道的默认规则。
5. **Given** 一次通知发送结果未知, **When** 查看系统状态, **Then** 该次尝试留痕并转入待处理,不盲目自动重发。

### User Story 6 - 订单同步与人工交付动作(增强既有订单页) (Priority: P6)

卖家在"订单管理"页可发起"一键同步订单":选择账号(或全部)创建后台同步任务,页面轮询进度,完成后报告按账号的恢复/修正/新增数量与失败明细,可中途取消;订单行提供"单笔同步"。对已核验、待交付的订单提供"人工触发交付"(按既有规则匹配并发送给买家,记录原因与幂等键,绝不重复交付);对已交付订单提供"人工确认平台已发货"(记录原因,与消息交付状态独立)。

**Why this priority**: 同步与人工兜底把订单从"被动等事件"补齐为"主动核对",是宪章漏单补偿的人工入口;复用既有任务与人工动作设施,增量小、价值高。

**Independent Test**: 对演示账号触发一键同步,观察任务进度与结果汇总;对一笔待交付订单执行人工触发交付,验证仅此一次发送且留痕。

**Acceptance Scenarios**:

1. **Given** 两账号共 5 笔平台侧订单, **When** 一键同步完成, **Then** 结果按账号列出新增/恢复/修正/失败明细。
2. **Given** 同步任务运行中, **When** 点击取消, **Then** 任务安全收尾后停止,页面如实报告已处理部分。
3. **Given** 一笔付款事实齐备且未交付的订单, **When** 人工触发交付, **Then** 走既有交付管线(核验→预留→发送→确认),内容与自动交付一致,重复触发被幂等拒绝。
4. **Given** 一笔已交付但平台未标记发货的订单, **When** 人工确认平台已发货, **Then** 平台确认状态独立记录,不影响消息交付记录,原因留痕。
5. **Given** 付款事实缺失的订单, **When** 尝试人工触发交付, **Then** 操作不可用并说明缺哪些核验要素,系统不猜测。

### User Story 7 - 系统与 AI 设置(管理员运营配置) (Priority: P7)

管理员打开"系统与AI"页(原设置页扩展):AI 配置区填写 API 地址、API Key(脱敏回显)、模型(支持拉取可用模型列表)、"测试连接"返回模型与耗时;账号 AI 自动回复提供开关与自定义提示词,并明确 AI 仅生成客服回复文案、不参与发货或付款判断;安全区提供管理员用户名/密码修改(需当前密码,改密后其他会话全部失效)。

**Why this priority**: AI 自动回复是 Ydisks 的差异化能力,凭据修改是安全运维刚需;两者独立于其他域,放最后不阻塞核心链路。

**Independent Test**: 配置 AI 服务后点击"测试连接"查看返回;修改管理员密码后,旧会话访问被要求重新登录,新密码可登录。

**Acceptance Scenarios**:

1. **Given** 填写 AI API 地址与密钥, **When** 点击"读取模型"/"测试连接", **Then** 分别返回模型列表与含模型名、耗时、回复摘要的测试结果;失败显示原因。
2. **Given** API Key 已配置, **When** 重新打开设置页, **Then** 密钥显示"已配置"占位,不回显明文。
3. **Given** 账号 AI 自动回复开启, **When** 买家发来普通消息, **Then** AI 生成回复并发送;整个过程不改变订单状态、不触发交付。
4. **Given** AI 服务不可用, **When** 买家发来消息, **Then** 系统静默降级不回复,不影响其他自动化,失败留痕可查。
5. **Given** 管理员修改密码成功, **When** 另一已登录会话继续操作, **Then** 会话失效并回落登录页。

---

### Edge Cases

- 卡密组余量为 0 或不足订单份数:不猜测、不部分交付,订单转待处理并说明缺口。
- API 取卡返回结果未知(超时/无法解析)且不支持查询:该卡不回库、不重新分配,转人工核对,保留请求标识与返回内容。
- 同一订单自动与人工动作并发:经既有执行互斥机制保证仅一个动作生效,后来者被明确拒绝并提示原因。
- 规则引用对象被删(卡组/模板/商品):规则自动标记"需重新配置"并禁用执行,列表可见警示,不静默失败。
- 聊天输入为空/超长/仅空白:发送按钮禁用或拒绝,并提示限制;图片超限或格式不符在预览阶段拦截。
- 消息与会话中的未知消息类型、未知订单状态、未知渠道配置:按既有"未知枚举安全渲染"原则显示占位,不崩溃、不误判。
- 通知渠道配置错误(签名错误/网络不可达):测试与真实发送均返回结构化失败原因,不静默吞掉。
- 求评计划在账号停用、授权失效期间到达执行时间:跳过并记录,恢复后不补发超过次数上限的提醒。
- 自定义时间范围开始晚于结束(概览/订单筛选):拒绝并提示,不产生空结果误导。
- 所有列表页在加载/错误/无数据/筛选无匹配四种状态下均有明确占位,错误可重试。

## Requirements *(mandatory)*

### 横切约束

- **FR-001**: 侧边导航 MUST 对齐参考页面顺序呈现:概览(仪表盘)、账号管理、在线聊天、卡密库存、商品列表、订单管理、发货模板、自动化规则、待处理(本项目自有能力,保留)、通知设置、系统与AI;原"商品与规则"合并入口拆分为"商品列表"与"自动化规则"两个独立页面,原有功能不回退;在线聊天侧边栏项 MUST 显示未读徽标。
- **FR-002**: 每个新增能力域(卡密库存、发货模板、自动化规则扩展、聊天、通知、系统与AI)MUST 作为独立限界上下文组织:领域层承载业务规则与状态机,应用层以用例编排并经仓储接口持久化,平台与外部服务经端口适配,交互层只做调用与呈现;跨域访问 MUST 经应用层用例或端口,不得跨域直写存储。
- **FR-003**: 界面上的全部入口、徽标与开关 MUST 仅映射系统真实具备且已验证的能力;依赖平台写操作或未验证平台能力(商品发布/批量铺货、改价、自动评价、每日擦亮、发送商品卡片、历史会话回填等)的功能 MUST NOT 在未验证前提供可用入口,并按本规格"范围外"处理。
- **FR-004**: 新增一切外部动作(通知发送、API 取卡、聊天发送、AI 调用)MUST 持久化尝试与结果,并遵守既有结果分类:确定成功/确定未发送/结果未知;结果未知时停止自动重发并转人工核对。
- **FR-005**: 破坏性操作(删除卡组、模板、渠道、会话隐藏、清空记录、改密)MUST 走既有统一确认流;所有新接口沿用既有认证、CSRF、错误信封与审计约定。

### 卡密库存域

- **FR-010**: 系统 MUST 支持四类卡密组的创建、编辑、启用/停用与删除:批量库存(data)、固定文本(text)、图片链接(image)、API 取卡(api)。
- **FR-011**: 批量库存组 MUST 逐行保存卡密条目并实时显示可用余量;支持向既有组粘贴追加(空行忽略,追加前预览有效条数);卡密内容 MUST 经既有加密路径存储,列表与详情不以明文批量回显。
- **FR-012**: 系统 MUST 提供表格批量导入(电子表格/CSV/TSV,含模板下载),导入结果 MUST 给出总行/成功/失败数与逐行错误定位;仅成功行入库。
- **FR-013**: API 取卡组 MUST 支持配置请求地址、方法、超时、请求头、参数、请求体与响应取值路径,提供不落库的一次性"测试"请求;真实取卡 MUST 保存请求标识与返回内容,支持重试开关。
- **FR-014**: 卡密组 MUST 支持组级延时发货(0–3600 秒,0 为立即)与描述;规则可覆盖该延时。
- **FR-015**: 交付执行 MUST 从匹配的卡密组按"原子预留→绑定订单→发送→确定成功后扣减"处理:预留时即取卡,内容加密快照并绑定订单,后续发送使用该快照;并发下同一卡不得分配给两个订单,结果未知时不得回库或换卡(宪章 I)。
- **FR-016**: 被规则或模板引用的卡密组删除 MUST 提示引用并要求显式确认;确认删除后引用它的规则自动转为"需重新配置"并停用执行。
- **FR-017**: 概览页 MUST 新增"库存卡密余量"统计卡,数值为全部启用批量组的可用余量之和,与订单/库存动作实时一致。

### 发货模板域

- **FR-020**: 模板 MUST 由名称、启用状态与至少一条有序消息组成,支持增删消息与调整顺序;模板内容沿用规则内容既有的大小与加密约束。
- **FR-021**: 消息 MUST 支持变量占位符:买家昵称、订单号、买家 ID、卡密组名、卡密变量(绑定卡密组)、自定义变量(规则内赋值);变量命名 MUST 校验,拼写错误在保存时指出。
- **FR-022**: 规则选用模板后 MUST 逐个绑定模板卡密变量到卡密组并填写自定义变量取值;渲染 MUST 以订单事实为源,预览与实际发送一致。
- **FR-023**: 被规则引用的模板 MUST 不可删除,删除请求返回引用信息。

### 自动化规则域

- **FR-030**: 付款自动发货规则 MUST 支持多规格变体:按规格名称/规格值匹配不同发货内容(卡密组或模板),支持每件份数(1–100)与覆盖组级延时;多规格状态以平台事实为准。
- **FR-031**: 规则 MUST 支持优先级(数字越小越高);同账号同商品同触发类型允许多条启用规则并存,仅执行最高优先级的一条,不得重复交付;同范围同触发且同优先级的重复规则 MUST 拒绝保存(001"同范围仅一条启用规则"约束按此修订,见 Clarifications)。
- **FR-032**: 账号级规则(覆盖全部商品)MUST 经显式确认"适用于全部商品"后方可在真实订单上执行,未确认前标记"需确认·暂不发货"(宪章:覆盖全部商品的规则必须显式配置)。
- **FR-033**: 关键词回复规则 MUST 支持关键词包含匹配、回复文字或图片、关联多商品或账号级、同会话只回复一次;关键词回复 MUST NOT 触发交付或改变订单状态。
- **FR-034**: 账号默认回复 MUST 支持每账号启用/停用、兜底文案(文字/图片)、只回复一次与清空回复记录。
- **FR-035**: 超时求评规则 MUST 基于已交付订单的计划扫描(默认每小时一次,账号停用/离线时跳过并留痕),支持发货后等待小时、再次求评间隔、最多次数与文案;达上限后停止。
- **FR-036**: "评价后发送赠品"触发 MUST 仅在平台适配器声明并验证评价事件能力后开放,未验证时入口隐藏(能力门禁)。
- **FR-037**: 自动化执行失败或结果未知 MUST 转入既有待处理体系,携带允许的处置(安全重试/继续下一步/终止)与上下文,处置全程留痕;延迟任务支持重试/忽略。
- **FR-038**: 规则列表 MUST 支持按触发类型/状态/关键词筛选与分页;规则卡 MUST 展示触发类型、关联范围、动作摘要与警示状态。
- **FR-039**: 既有"固定内容"发货方式 MUST 与卡密组、发货模板并存为并列的内容来源,存量规则数据零迁移,既有规则页面行为不回退。

### 在线聊天域

- **FR-040**: 聊天页 MUST 按账号呈现会话列表与消息面板:会话支持搜索(用户/商品/消息)、只看未读切换、分页加载;消息支持游标式"加载更早";消息类型至少涵盖文本、图片、系统通知与商品卡片样式展示。
- **FR-041**: 在线账号 MUST 可发送文本(限 2000 字)与图片(≤10MB,粘贴先预览确认);发送状态 MUST 覆盖发送中/已发送/失败(可重试)/结果未知(不可自动重试)。
- **FR-042**: 图片发送与历史会话回填 MUST 以适配器能力声明为门禁:未验证时对应入口隐藏或禁用并如实说明,不得虚报(宪章 I/III)。
- **FR-043**: 系统 MUST 持久化会话与消息(本地接入后的收发记录),未读状态按会话聚合并在账号 Tab 与侧边栏展示,打开会话后清零。
- **FR-044**: 快捷回复 MUST 支持新增/复制/发送/删除,上限 50 条;买家备注 MUST 仅对卖家角色会话开放查看与编辑。
- **FR-045**: 删除会话 MUST 仅本机隐藏并清空展示消息,不影响平台侧数据,且需确认。
- **FR-046**: 消息实时性首版采用轮询(可见时 ≤3 秒,页面不可见暂停),WebSocket 推送列为后续增强;轮询与既有事件管道 MUST NOT 产生重复消息记录。

### 通知渠道域

- **FR-050**: 系统 MUST 支持 Webhook、邮件(独立 SMTP/复用系统 SMTP)、钉钉、飞书、企业微信、Bark、Telegram 七类渠道的创建、编辑、启停与删除;秘密字段编辑时 MUST 脱敏回显,留空保存表示不修改。
- **FR-051**: 每渠道 MUST 可订阅事件类型(账号掉线/恢复、需要人工处理、安全验证、交付结果、系统错误等;不选=全部),支持发送测试并返回结构化成功/失败。
- **FR-052**: MUST 支持按账号绑定渠道(覆盖式)与默认发送规则(未绑定账号事件发送至全部启用渠道)。
- **FR-053**: 管理员 MUST 可配置系统级 SMTP(服务器/端口/账号/凭据/发件人/加密方式,凭据脱敏)。
- **FR-054**: 通知发送 MUST 持久化尝试与结果;结果未知转待处理,不盲目自动重发。

### 订单同步与人工交付动作

- **FR-060**: 系统 MUST 支持按账号(或全部账号)发起订单同步后台任务,语义为按账号全量对账(新增/恢复/修正),复用既有事件摄取与漏单补偿逻辑,离线账号跳过并注明:进度可轮询、可安全取消,完成后按账号报告明细;订单行支持单笔同步。
- **FR-061**: 对付款事实齐备且未交付的订单 MUST 提供"人工触发交付":走既有交付管线与执行互斥,幂等拒绝重复触发,原因与操作人留痕。
- **FR-062**: MUST 提供"人工确认平台已发货"动作:独立记录平台确认状态,不影响消息交付记录,需原因留痕。
- **FR-063**: 核验要素缺失时人工触发交付 MUST 不可用,并指明缺失要素;系统不得以人工发起为由跳过核验。
- **FR-064**: 订单事实(金额/状态/买家信息等)MUST 保持平台事实模型,不提供自由编辑;纠偏经人工动作与恢复核对体系留痕进行。

### 系统与AI域

- **FR-070**: 系统与AI页 MUST 提供 AI 配置:API 地址、API Key(脱敏)、模型选择(支持按服务拉取模型列表)、测试连接(返回模型名、耗时、回复摘要);配置失败给出结构化原因。
- **FR-071**: 账号 AI 自动回复 MUST 为账号级开关+自定义提示词;AI 输出仅作为客服回复文案,MUST NOT 参与发货决策、付款判断或改价;买家消息自动回复分流顺序 MUST 为:关键词匹配(商品级优先→账号级)→ AI 回复(开启时)→ 账号默认回复兜底,命中即止,环节失败顺延下一环节;生成内容沿用消息长度限制;AI 不可用时静默降级并留痕,不阻塞其他自动化。
- **FR-072**: 管理员 MUST 可修改用户名与密码:需验证当前密码,新密码沿用既有强度要求;改密成功后除当前会话外全部会话 MUST 失效。
- **FR-073**: 系统与AI页 MUST 保留既有设置页信息(运行信息、能力声明、备份指引),不回退。

### Key Entities *(include if feature involves data)*

- **卡密组(CardPool)**:名称、类型(批量/文本/图片/API)、启用、延时、描述;批量组含卡密条目(状态:可用/预留/已使用/失效,预留绑定订单),API 组含请求配置与取值路径。
- **发货模板(DeliveryTemplate)**:名称、启用、有序消息列表、变量引用(卡密变量→卡密组、自定义变量)。
- **自动化规则(AutomationRule)**:触发类型(付款发货/超时求评/评价赠品[能力门禁]/关键词回复/默认回复)、生效范围(账号/商品/规格变体)、内容来源(卡密组/发货模板/固定内容[存量])、动作(发送卡密/发送模板/发送赠品/求评提醒)、每件份数、优先级、启用状态、全部商品确认标记、需重新配置标记。
- **会话(Conversation)与消息(Message)**:所属账号、对端买家、未读计数、消息类型、方向、发送状态、本地隐藏标记;买家备注按买家维度。
- **通知渠道(NotificationChannel)**:类型、配置(秘密脱敏)、启用、事件订阅集;账号-渠道绑定。
- **AI 配置(AiSettings)**:系统级(地址/密钥/模型)与账号级(开关/提示词)。
- **同步任务(复用既有任务机制)**:类型=订单同步,进度、结果汇总与逐账号明细。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 侧边导航与参考页面逐项对齐(11 项含本项目"待处理"),每个新页面从导航一步可达,缺失项为 0。
- **SC-002**: 卡密库存全链路(建组→导入→规则绑定→订单预留→发送→扣减)可在一套演示数据下完整走通,并发下重复分配率为 0,余量与实际状态一致率 100%。
- **SC-003**: 模板变量渲染预览与实际发送内容一致率 100%;被引用模板删除拦截率 100%。
- **SC-004**: 同范围同触发规则并发命中时重复交付为 0;未确认的账号级规则执行次数为 0。
- **SC-005**: 聊天发送的四种状态可见率 100%;结果未知消息的自动重发次数为 0。
- **SC-006**: 配置正确的通知渠道测试成功率 100%(接收端确认),订阅外事件误发率为 0。
- **SC-007**: 七个用户故事各自可独立验收交付,任一故事单独完成即可演示对应页面价值,相互阻塞数为 0。
- **SC-008**: 验收走查中"虚标能力"(入口存在但能力未验证)出现数为 0;新增代码均落位于对应限界上下文,跨域直写存储为 0。

## Assumptions

- **范围外(后续特性,不在本规格实现)**:商品发布与批量铺货、类目推荐、商品编辑/删除/手动建档、拍下改价、自动评价、每日擦亮、订单字段编辑、邮箱验证码登录、密码登录刷新授权(Ydisks 自身已禁用)、聊天发送商品卡片、WebSocket 实时推送、仪表盘商品销量排行/下单占比/金额分析图表(概览统计口径刚由 005 收口,图表增强留待独立特性)。上述能力依赖未验证的平台写操作或属独立统计增强,按宪章"如实展示"不虚标。
- 能力门禁机制沿用既有能力声明接口:适配器验证通过并声明后,对应入口(评价赠品触发、图片发送、历史回填)在界面开放。
- 事件类型集合以本项目既有事实为准(掉线/恢复/人工处理/安全验证/交付结果/系统错误),不照搬 Ydisks 的改价/评价类事件。
- AI 服务为用户自行配置的外部服务,系统仅做 HTTP 调用与凭据脱敏存储,不内置任何第三方代理;调用受既有超时与重试预算约束。
- 目标用户为个人卖家:账号数十以内、卡密数千、消息数万级,列表采用分页/游标与既有查询模式,不引入外部检索设施。
