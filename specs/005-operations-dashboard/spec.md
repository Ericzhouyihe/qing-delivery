# Feature Specification: 运营概览统计首页(005-operations-dashboard)

**Feature Branch**: `005-operations-dashboard`

**Created**: 2026-09-25

**Status**: Draft

**Input**: User description: 把轻交付的概览首页改造成与 Ydisks 闲鱼助手一致的运营统计页面——时间范围筛选(今天/昨天/三天内/7天内/一个月内/自定义)、四张统计卡(累计营收、活跃账号/总数、订单数、库存卡密余量)、营收趋势分析图表;后端如需修改,严格按照 DDD 领域化的方式新增功能或修改代码。

## Clarifications

### Session 2026-09-25

- Q: 已付款后发生退款或交易关闭的订单,是否仍计入营收合计与订单数? → A: 计入(付款事实口径)——按付款事实统计,退款不回冲;退款对账在订单中心逐单查看。
- Q: "三天内/7天内/一个月内"这些预设范围,应该如何确定起止时刻? → A: 自然日对齐——三天内=含今天共 3 个自然日,7天内=含今天共 7 个自然日,一个月内=含今天共 30 个自然日;"昨天"=前一自然日;起点为当日 00:00(本地时区)。
- Q: 参考页面第四张卡是"库存卡密余量",但本项目首版不支持卡密——这张卡应该放什么内容? → A: 待人工处理——沿用现有开放事项计数与下钻入口;未来引入卡密库存域后可替换该卡位。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 时间范围筛选与四张统计卡 (Priority: P1)

卖家打开概览首页,看到"运营概览"标题区(附系统运行状态指示)与一排时间范围筛选(今天/昨天/三天内/7天内/一个月内/自定义,默认 7天内)。筛选下方并排四张统计卡:①累计营收(所选区间内已付款订单金额合计,附与前一等长区间对比的涨跌徽标);②活跃账号 / 总数(在线账号数 / 账号总数);③订单数(所选区间内付款订单数);④待人工处理(当前开放事项数,点击可下钻)。切换范围时四张卡的数值原地更新,不整页刷新。

**Why this priority**: 统计卡是卖家打开首页第一眼要看的经营事实;"按时间范围看数据"是与参考页面一致性的核心,也是趋势图的前提。

**Independent Test**: 造 2 笔已知金额与付款时间的订单,分别选"今天"与"7天内",核对营收与订单数变化且四张卡同步更新。

**Acceptance Scenarios**:

1. **Given** 系统内存在区间内的已付款订单(金额、时间已知), **When** 卖家选择某时间范围, **Then** 累计营收卡显示该区间已付款订单金额合计(CNY),订单数卡显示该区间付款订单笔数。
2. **Given** 所选区间的前一等长区间存在数据, **When** 渲染营收卡, **Then** 涨跌徽标按(本区间 − 前一区间)/前一区间显示百分比,上涨/下跌有可区分的视觉状态。
3. **Given** 前一等长区间无任何订单, **When** 渲染营收卡, **Then** 对比徽标隐藏或显示"无对比",不显示误导性的 0%。
4. **Given** 存在已连接(在线)账号 1 个、账号总数 2 个, **When** 渲染账号卡, **Then** 显示"1 / 2"。
5. **Given** 存在开放的人工处理事项 4 个, **When** 渲染待处理卡, **Then** 显示 4 并提供进入待处理工作台的下钻入口;为 0 时不告警样式。
6. **Given** 卖家从一个范围切换到另一范围, **When** 数据返回, **Then** 四张卡数值原地更新,页面不跳动、不整页刷新。
7. **Given** 服务正在停止或恢复隔离, **When** 渲染标题区, **Then** 运行状态指示呈对应状态,既有告警横幅仍置顶显示。

### User Story 2 - 营收趋势分析图表 (Priority: P2)

时间筛选下方呈现"营收趋势分析"区块,展示所选范围内的销售额走势:区间不超过 48 小时按小时汇总,更长区间按本地自然日汇总;柱/点可读出每个时间桶的营收。范围内无订单时显示明确空态("暂无营收数据 / 所选时间范围内暂无订单记录"),而不是画一张空图。

**Why this priority**: 趋势是"运营概览"区别于简单计数表的核心价值,但依赖统计卡先确定区间与口径,故列第二。

**Independent Test**: 造 3 笔分布在两个不同自然日的订单,选"7天内",图表在这两日出现非零走势点,合计金额与营收卡一致。

**Acceptance Scenarios**:

1. **Given** 区间内订单分布在一个或多个自然日, **When** 渲染趋势图, **Then** 每个时间桶的金额等于该桶内已付款订单金额合计,全区间合计与累计营收卡一致。
2. **Given** 所选范围为"今天"或"昨天", **When** 渲染趋势图, **Then** 按小时粒度展示且桶边界为本地时区自然小时。
3. **Given** 所选范围内无任何已付款订单, **When** 渲染趋势区, **Then** 显示空态图文,明确说明"所选时间范围内暂无订单记录"。
4. **Given** 趋势图渲染中或查询失败, **When** 查看区块, **Then** 呈现加载/错误占位,不影响统计卡独立展示。

---

### User Story 3 - 自定义时间范围 (Priority: P3)

卖家选择"自定义"后,可指定起始与结束日期(含两端,按本地时区解释),跨度最大 92 天;确认后统计卡与趋势图按该区间重新查询。跨度超限或结束早于起始时,给出明确提示且不发起查询。

**Why this priority**: 补齐预设范围之外的对账场景(如按月度对账),使用频率低于预设范围。

**Independent Test**: 选择一个跨两周的自定义区间,统计卡与趋势图数据与该区间内已知订单一致;输入倒置区间时被拦截并提示。

**Acceptance Scenarios**:

1. **Given** 卖家选择起止日期为同一天, **When** 确认, **Then** 统计该自然日(本地时区 00:00 至 24:00)的数据。
2. **Given** 卖家选择的结束日期早于起始日期, **When** 确认, **Then** 系统提示区间无效,不发起查询、不改变当前展示。
3. **Given** 卖家选择的跨度超过 92 天, **When** 确认, **Then** 系统提示最大跨度并阻止查询。
4. **Given** 自定义查询完成, **When** 卖家在页面上手动刷新或等待自动刷新, **Then** 仍按该自定义区间刷新数据。

---

### Edge Cases

- 所选区间内无任何订单:统计卡显示 0/空值占位,趋势区显示空态,不渲染误导性的 0% 对比徽标。
- 订单金额缺失或币种非 CNY:不计入营收合计(口径见 FR-010),订单数是否计入以付款事实为准;口径在界面上不产生歧义。
- 订单在付款后发生退款或交易关闭:仍按付款事实计入区间营收与订单数,退款带来的净额差异由订单中心逐单核对,统计卡片不回冲。
- 账号总数为 0(新装系统):账号卡显示"0 / 0"并引导接入,趋势区与营收卡走空态。
- 恢复隔离/服务停止中:告警横幅置顶不受改版影响;统计照常展示可用数据。
- 自动刷新落在范围切换的瞬间:以最后一次选择的范围为准,不出现旧范围数据覆盖新范围。
- 本地时区跨日(如深夜 23:59 付款、次日 00:01 入账):按本地自然日/自然小时分桶,与既有"今日订单"口径一致。
- 统计服务不可用:统计卡显示"统计不可用"占位而非错误弹窗,页面其余区块照常。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 概览首页 MUST 呈现"运营概览"标题区,包含页面标题、欢迎/说明副文案与系统运行状态指示(正常/停止中/恢复隔离)。
- **FR-002**: 系统 MUST 提供时间范围筛选:今天、昨天、三天内、7天内、一个月内、自定义;默认选中 7天内;所有范围按本地时区解释。预设范围按自然日对齐:今天=当日 00:00 起;昨天=前一自然日全天;三天内=含今天共 3 个自然日;7天内=含今天共 7 个自然日;一个月内=含今天共 30 个自然日。
- **FR-003**: 系统 MUST 展示累计营收卡:所选区间内已付款订单金额合计(CNY),并附与前一等长区间的对比徽标;前一区间无数据时不得显示百分比。
- **FR-004**: 系统 MUST 展示活跃账号卡:在线(已连接)账号数 / 账号总数,并提供进入账号管理的下钻入口。
- **FR-005**: 系统 MUST 展示订单数卡:所选区间内付款订单笔数,并提供进入订单中心的下钻入口。
- **FR-006**: 系统 MUST 展示第四张统计卡:当前开放人工处理事项数,提供进入待处理工作台的下钻入口;事项数大于 0 时使用警示样式。(首版无卡密库存域,以"待人工处理"承载第四卡位;若后续引入库存卡密能力,该卡位可替换为库存卡密余量。)
- **FR-007**: 系统 MUST 展示营收趋势分析区块:按所选区间绘制销售额走势;区间 ≤48 小时按小时分桶,其余按本地自然日分桶;每桶金额为该桶内已付款订单金额合计。
- **FR-008**: 区间内无数据时,趋势区 MUST 显示明确空态;统计卡显示 0 或空值占位,不渲染对比徽标。统计查询失败时,趋势区 MUST 显示错误占位(可重试),四张统计卡保留上次值或显示占位,不得闪现为 0。
- **FR-009**: 自定义范围 MUST 支持起止日期选择(含两端、本地时区),跨度上限 92 天;区间倒置或超限时提示且不发起查询。
- **FR-010**: 营收口径 MUST 为:`paid_at` 落在所选区间内的已付款订单,仅累计 CNY 金额;金额缺失或非 CNY 的订单不计入营收合计但计入订单数(若其构成付款事实)。付款后发生退款或交易关闭的订单 MUST 仍计入营收合计与订单数(付款事实口径,退款不回冲);聚合不得按退款/关闭状态过滤。
- **FR-011**: 后端统计能力(区间营收合计与对比、区间订单数、趋势序列、账号活跃快照)MUST 作为独立只读统计用例新增:聚合逻辑置于应用层统计服务,数据访问经仓储端口完成,订单/账号聚合口径由领域层定义;HTTP 传输层只做鉴权与调用,不得内联聚合查询或 SQL(宪法原则 II:平台接入与发货业务分离)。
- **FR-012**: 统计查询 MUST 为只读,不改变订单、账号、事项的任何状态,不触发交付或值守副作用。
- **FR-013**: 概览页 MUST 保留既有 30 秒可见性自动轮询与手动刷新;刷新与轮询按当前所选范围重新查询,切换范围后不得回落到其他范围。
- **FR-014**: 概览页 MUST 在新增统计区之下保留既有运营区块(账号状态速览、最近待处理、最近订单)及其下钻行为。
- **FR-015**: 范围切换与刷新 MUST 原地更新数值与图表,不整页刷新、无明显布局跳变("无明显跳变"判据:数值节点原地复用不重建,容器高度仅随内容变化一次性调整)。
- **FR-016**: 统计查询 MUST 与既有管理接口一致要求管理员授权。

### Key Entities *(include if feature involves data)*

- **统计区间(StatsRange)**:一次统计的起止时刻与分桶粒度;由预设范围或自定义起止日期解析而来,本地时区语义,两端包含。
- **营收汇总(RevenueSummary)**:区间内营收合计、付款订单数、前一等长区间的营收合计(用于对比徽标)。
- **营收趋势点(RevenueTrendPoint)**:单个时间桶的起始时刻、营收金额、订单笔数;桶粒度随区间时长确定。
- **账号活跃快照(AccountActivitySnapshot)**:当前在线(已连接)账号数与账号总数;任一时刻只有一个"当前值",不随统计区间变化。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 卖家切换任意时间范围后,2 秒内看到统计卡与趋势图更新完成。
- **SC-002**: 任意区间内,营收合计与订单数与订单中心逐单人工核对结果 100% 一致(口径按 FR-010)。
- **SC-003**: 7天内范围、1 万笔订单规模下,统计查询在 3 秒内返回完整结果。
- **SC-004**: 无数据场景(新区间/新装系统)100% 呈现空态或占位,无误导性数值。
- **SC-005**: 对比徽标在 10 组相邻等长区间样本中与手工计算结果完全一致。
- **SC-006**: 首次打开概览页的卖家在不培训的情况下能说出"这段时间卖了多少、多少单、有没有要人工处理的"。

## Assumptions

- 第四张统计卡为"待人工处理"(已澄清确认):当前产品首版明确不支持卡密(无库存卡密域可统计),故以开放事项计数承载第四卡位;未来引入库存域时可替换,不影响其余三卡与趋势图。
- 默认选中范围与参考截图一致为"7天内";预设范围为自然日对齐区间(见 FR-002,已经澄清确认),趋势分桶与区间边界天然对齐。
- 营收仅累计 CNY;当前业务只有闲鱼(CNY)结算,多币种处理不在本特性范围。
- 趋势分桶粒度规则(≤48 小时按小时、其余按日)为合理默认,与参考项目"7天内的销售额走势"行为兼容。
- 既有运营区块(账号速览/最近待处理/最近订单)保留在改版后的页面下方:它们是值守运营的日常工作入口,参考截图未展示全页,不视为冲突。
- 自定义区间跨度上限 92 天(约一个季度),兼顾对账场景与查询性能。
- "活跃账号"定义为连接状态在线的账号;与账号页状态徽标口径一致。
